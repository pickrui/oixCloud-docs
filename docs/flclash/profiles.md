# 配置、订阅与更新

FlClash for oixCloud 可以使用兼容的第三方节点和订阅，普通导入不要求先登录 oixCloud 账户。以下按当前维护版本的入口说明；没有对应选项时，先核对 [安装版本](/flclash/connect#downloads)

| 我想要 | 使用方法 |
| --- | --- |
| 在现有配置中加入一个节点 | [添加自定义节点](#single-node) |
| 单独使用另一家的订阅 | [导入并切换配置](#other-subscription) |
| 同时使用第三方与托管节点 | [保留托管配置，追加节点或代理提供者](#managed-mix) |

## 托管配置与普通配置

| 配置来源 | 导入入口 | 更新方式 |
| --- | --- | --- |
| oixCloud 托管配置 | 登录 oixCloud 后自动导入 | 通过账户与托管配置管理入口刷新、同步 |
| 第三方订阅 URL | 「配置 → 添加配置 → 链接」，填写完整 URL | 从远程订阅同步 |
| 本地文件 | 「配置 → 添加配置 → 文件」，选择文件 | 没有远程 URL 可供刷新 |

客户端一次应用一份配置。选择配置并启动后，确认代理列表已经变为这份配置的内容；列表中保存了多份配置，不代表它们的节点和规则已自动合并

## 添加单个第三方节点 {#single-node}

适合已有可用配置，希望加入一个自建或第三方节点的情况，也可直接加在 oixCloud 托管配置中

新增前准备一个独立名称：**与原配置中的节点同名会覆盖该节点的定义**，而不是增加第二个同名节点；不要使用已有策略组或 `DIRECT`、`REJECT` 等内置策略的名称

1. 打开「配置」，找到要使用的配置，打开它的操作菜单，进入「链式代理」
2. 在「自定义节点」区域点「新增」，按手头的信息选择输入方式
3. 核对名称、服务器、端口和认证信息后保存，确认该节点的开关已开启
4. 选中这份配置并应用，回到「代理」中的手动选择组，选择刚加入的节点；重新访问目标网站，在 [连接记录](/flclash/diagnostics) 中核对出口

| 输入方式 | 填写内容 |
| --- | --- |
| URI | 一条完整的节点分享链接，例如 `ss://`、`vmess://`、`vless://`、`trojan://` 或 `hy2://`，其余格式以输入框提示和校验结果为准 |
| 快速编辑 | 选择代理类型，填写名称、服务器、端口及该协议要求的密码、UUID、TLS、传输等参数 |
| YAML | 一个完整节点定义，或仅含一个节点的 `proxies:` 列表；不能粘贴整份多节点订阅 |

例如，下列内容只演示单节点 YAML 结构，服务器与密码均须替换为提供方的真实参数，不能直接连接：

```yaml
name: My-Third-Party
type: trojan
server: proxy.example.com
port: 443
password: replace-with-your-password
sni: proxy.example.com
udp: true
```

「自定义节点」虽位于「链式代理」页面，也能独立使用，**无需创建或开启代理链**。普通配置和托管配置会将启用的自定义节点追加到原有的手动选择组。自动测速、故障转移及叠加覆写中的个人策略组是否包含新节点，取决于组的成员选择和「包含所有代理」等设置，应在相应组中核对

自定义节点只属于所编辑的配置，并在订阅更新后重新加入

### 将分享链接单独导入 {#standalone-node}

不依附现有配置时，也可在「配置 → 添加配置 → 链接」粘贴 `ss://`、`vless://` 等受支持的分享链接，客户端会保存为本地配置。它不会自动并入托管配置，也没有远程订阅可供同步

单节点链接只提供节点参数，不附带提供方的完整分流规则。若希望这份配置将剩余流量交给该节点：

1. 选中导入的配置，打开其「覆写」，选择「叠加」
2. 在「规则」中新增 `MATCH` 规则，目标选择刚导入的节点；`MATCH` 不填写域名，会匹配前面的规则尚未处理的全部流量，应放在个人规则末尾
3. 保存后使用「检查配置」或「立即应用」，保持规则模式，发起新连接核对出口

需要保留国内直连等完整分流时，优先导入提供方的完整 Clash / mihomo 配置，或按 [覆写与附加规则](/flclash/rules) 先安排更具体的规则

HTTP / HTTPS 代理的 `http://`、`https://` 链接请使用前面的「自定义节点 → URI」入口；「添加配置 → 链接」会把 HTTP / HTTPS 地址当作远程订阅下载

## 导入其他订阅或配置文件 {#other-subscription}

1. 从提供方取得 Clash / mihomo 兼容订阅的完整 URL；账户网页、购买页和一条节点分享链接不是同一种内容
2. 打开「配置 → 添加配置 → 链接」，填写便于区分的名称和完整 URL，确认导入。也可从「二维码」入口读取订阅链接，或选「文件」导入已经下载的 YAML 配置
3. 等待下载与校验成功，在配置列表中选中新配置，启动或应用客户端
4. 打开「代理」，在这份配置对应的策略组中选择节点，使用新连接核对规则与出口。需要用回托管节点时，在「配置」中重新选中 oixCloud 托管配置

URL 订阅在该配置的操作菜单中点「同步」更新，也可在「编辑」中设置自动更新与间隔。本地文件只是导入时的副本，原文件变化不会自动更新客户端，应重新导入或编辑这份配置

「添加配置 → 导入配置」是另一种入口：从 URL、文件或文本提取节点、策略组、规则和支持的设置，组建可编辑的「自定义配置」，不会把原 URL 保留为整份订阅的同步来源。需要持续跟随原订阅时，使用上面的「链接」入口。**将整份配置导入已有自定义配置会替换现有节点、策略组、规则和设置**，应先 [备份](/flclash/backup)，并查看「未导入」提示

## 与 oixCloud 托管节点一起使用 {#managed-mix}

希望继续使用托管分流，同时让部分流量走第三方节点时，保持 **oixCloud 托管配置为当前配置**，按下面的方法追加来源。混用节点不等于逐跳转发；只有明确需要入口、出口多跳连接时才配置 [代理链](/flclash/proxies#代理链)

### 加入一个或少量节点 {#managed-single-node}

按 [添加单个第三方节点](#single-node) 在托管配置中保存并启用节点，然后在托管配置原有的手动选择组中选中它。若只希望某个网站使用该节点，在托管配置的「覆写 → 叠加 → 规则」中添加域名后缀规则并将目标设为该节点，其余流量继续使用托管规则

### 加入整份第三方订阅 {#managed-subscription}

通过应用资源库将订阅作为「代理提供者」引用，可以更新第三方节点，同时保留托管配置的规则

1. 打开「工具 → 自定义配置资源 → 应用资源库」，切到「代理提供者」
2. 点添加按钮，选择「通过URL导入」，填写独立名称（例如 `ThirdParty`）和第三方订阅的完整 URL，检查来源为「远程地址」后保存。优先使用包含 `proxies:` 节点列表的 Clash / mihomo YAML；本地文件则用「通过文件导入」，不会从远程自动更新
3. 回到「配置」，打开 **oixCloud 托管配置** 的「覆写」，选择「叠加」，保留原有托管策略组与规则
4. 进入「代理组」新增一个独立名称的手动选择组（`select`），例如「第三方出口」。在成员选择器的「代理提供者」中勾选 `ThirdParty` 并保存；如需在同一组中切换托管出口，也可从可用成员中加入一个托管节点或原有托管策略组
5. 在同一覆写的「规则」中添加域名后缀 `example.com`，目标选「第三方出口」。保存后点「检查配置」或「立即应用」；保持规则模式，在「代理 → 第三方出口」中选择实际节点
6. 重新访问你设置规则的目标网站，在连接记录中确认命中个人规则、出口为所选第三方节点，再检查一个未设置个人规则的目标仍按托管规则处理

上面的域名与名称仅作示例，须改为实际目标。只创建策略组或保存资源不会让网站自动走该组，还需规则引用；新组也不会自动出现在原有手动选择组中。个人规则先于订阅规则，已有附加规则仍可能优先，详见 [覆写](/flclash/rules)

这种引用只使用第三方订阅中的节点，**不会同时套用另一家订阅的策略组、规则、DNS 或 TUN 设置**。代理提供者保留远程 URL；应用配置后，可从「代理」页的操作菜单进入「提供者」，使用更新按钮刷新相应代理提供者。账户页「同步」负责托管配置，另一份独立 URL 配置的「同步」也不等于更新此处的代理提供者

oixCloud 托管配置不能作为另一份「自定义配置」的代理提供者，也不能通过「导入配置」导入 oixCloud 托管地址。要混用，保留托管配置，再按上述步骤引用第三方来源

代理提供者的格式与字段说明见 [mihomo 官方代理集合文档](https://wiki.metacubex.one/config/proxy-providers/)

## 添加或导入失败时 {#import-troubleshooting}

| 现象 | 检查方法 |
| --- | --- |
| 分享链接无法识别或保存 | 检查是否完整、有无空格或换行及协议是否受支持；手动填写时核对认证、TLS、SNI 和传输参数，按编辑器报错修正 |
| 订阅下载失败或返回网页 | 检查原始 URL、有效期、提供方权限和网络；选择正确的 Clash / mihomo 格式，不要使用登录页地址 |
| 保存了节点，却在代理页找不到 | 确认编辑的是当前配置、节点开关已开启且配置已应用；检查手动选择组，个人策略组需显式添加成员 |
| 代理提供者已保存，组内仍没有节点 | 保存只登记来源；检查实际下载与解析结果、`proxies:` 内容、来源名称及组内筛选条件，在「提供者」更新后复查 |
| 添加后流量仍走原出口 | 检查规则模式、规则优先级、策略组选择和新连接的命中结果；导入成功本身不会切换出口 |

订阅地址和节点分享链接可能携带访问凭据，不要提交到公开 Issue 或不可信转换网站。回退前先移除个人规则、策略组和代理链对该节点或代理提供者的引用，再停用或删除新增项；不要通过删除托管配置来清理一个第三方节点

在「oixCloud → 节点筛选」按线路、地区和名称调整，检查预览并保存。保存后会自动刷新账户并同步托管配置，等待完成后检查节点；失败时按提示处理，再在账户页「同步」。恢复默认会使用智能优选；同一账户的同款客户端共享筛选，详见 [订阅与筛选](/account/subscriptions)

配置编辑页仍可调整「最小化配置」（精简规则）、TCP Fast Open 等支持项，没明确需求时保持默认。筛选不会提升套餐权限，不能保存保留节点数为零的条件

## 修改配置前

普通配置可预览或编辑内容，但订阅更新可能覆盖直接修改。希望长期保留个人规则和策略组时，使用 [覆写与附加规则](/flclash/rules)

托管配置保留专用管理方式，不能假定与普通 YAML 文件具有同样的导出或编辑入口

## 更新后核对四件事

1. 同步结果是否成功，而不是只看按钮已结束转动
2. 当前选中的配置是否就是刚更新的配置
3. 代理页是否出现筛选后应保留的节点，原来的节点选择是否还有效
4. 新连接是否使用预期规则与出口；旧连接可能仍沿用原先的路径

URL 配置依赖订阅服务可达，本地文件配置没有远程地址可供刷新。下载失败时先保留错误和旧配置，检查订阅有效期、账户权限及网络；反复新建同一个配置会增加排查难度
