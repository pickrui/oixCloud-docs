1. 打开「工具 → 进阶配置 → DNS」。要更改一般网站使用的解析器，点右上「＋」，添加「域名服务器」。若已添加，直接点这一项编辑列表，填入能从当前网络访问的 DNS 地址并确认
2. 保持这份配置启用，用测试应用访问一个之前没有查询过的有效域名。打开桌面侧栏的「DNS 查询」，窄屏或手机从「工具 → 更多 → DNS 查询」进入
3. 找到该域名并打开记录，核对「上游解析器」。如果命中缓存，换一个新域名再测。应用使用自己的加密 DNS 时，查询可能不会出现在这里
4. 要撤销这次修改，恢复之前的服务器列表；本次才添加的覆写项可直接移除，恢复继承

应用级覆写作用于各配置的相应字段。自定义配置自己的 DNS 设置优先，脚本和域名专用策略也会影响实际结果。节点本身需要其他解析器时，见下方字段表

## Fake-IP 与真实地址

DNS 模式会影响内核如何识别和路由域名。某些局域网或特定应用可能需要兼容设置；不要把所有域名加入例外，只调整已确认有问题的范围

## 本地端口与 DNS 劫持

混合端口在「工具 → 常规 → 端口」中查看；TUN 相关选项位于「工具 → 进阶配置 → 网络」。端口被其他程序占用时更换为未使用的端口，并同步更新手动配置代理的应用

macOS 的「自动设置系统DNS」在 TUN 运行时调整系统网络服务的 DNS；上方「域名服务器」决定内核选用的上游。公司内网解析失败时，确认公司 DNS 的可达性及域名路由，不能只换一个公共 DNS 服务器

## 节点域名解析失败

核对系统时间、客户端版本、当前配置与网络状态。Windows / macOS 的网络自检会区分系统 DNS、内核 DNS 与托管节点 DNS；单个解析失败不能直接认定令牌失效

## 先区分需要修改的字段

| 字段或开关 | 处理的环节 |
| --- | --- |
| 域名服务器 | 普通目标域名的解析 |
| 代理域名服务器 | 代理节点自身地址的域名解析 |
| 遵守规则 | DNS 连接按规则选择出站，需要避免解析与代理互相依赖 |
| 添加／移除覆写项 | 决定哪些字段覆盖配置；未添加项保持继承 |

节点域名都解析失败时，先检查代理域名服务器；公司内网域名失败时，先检查内网 DNS 与网络可达性。不要通过反复切换 fake-ip 和真实地址模式代替判断问题所在

更改前记录原值，用同一个域名和同一节点测试。开启 TUN 时，所谓「系统路径」也可能经过 TUN，自检对照结果需要结合当前接管状态阅读

## 只调整远程节点的 IPv4 出口 {#ipv4-only}

客户端 DNS 的 IPv6 选项和 TUN 接管设置不等于服务端出口限制。只希望目标网站看到 IPv4 时，使用 [IPv4 Only](/account/unlock#ipv4-only)，并核对流量确实经过所选支持节点；直连或绕过客户端的流量不受它控制

如果测试出现本地网络的解析器，按[DNS 泄漏排查](/flclash/dns-leaks)逐项检查托管配置、TUN 和 DNS 出站
