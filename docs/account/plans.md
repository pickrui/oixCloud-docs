# 购买、续费与切换

::: warning 套餐以有效期和流量为准
套餐同时受有效期与流量额度限制，**有效期结束或流量用尽，以先发生者为准，均代表当前套餐已耗尽**。即使尚未到期，流量用尽后也需要重新下单购买套餐，不能仅凭剩余有效期继续使用原套餐的高速流量；也可开启下面的自动重置流量

若已有待激活套餐、或开启了自动续费（仅到期时执行）与自动重置流量，系统会按下方的接续规则处理；请先到 [套餐管理](https://oixcloud.com/user/bought) 确认结果，未接续时再到 [套餐商店](https://oixcloud.com/user/shop) 下单，避免重复购买
:::

### 法币充值 {#fiat-top-up}

法币充值使用收银台当前显示的支付宝、微信等支付方式，具体可用方式和金额上下限以页面为准

1. 登录并打开 [收银台](https://oixcloud.com/user/v2/counter)，选择支付方式，输入充值金额
2. 核对输入框旁的 **CNY／USD**。CNY 是人民币订单金额；USD 仅用于参考换算，点击「核对金额」后确认人民币金额再下单。汇率不可用时使用 CNY
3. 提交订单，按当次二维码或支付链接完成付款，实际付款金额及费用以支付订单为准
4. 返回网站，在 [充值记录](https://oixcloud.com/user/code) 核对入账金额并刷新余额；若是套餐购买带来的补款，再检查套餐管理的实际购买结果

::: tip 法币充值遇到问题时刷新网页
使用法币充值遇到任何问题，可以**刷新收银台网页，让系统自动重新选择支付网关套件后再试**，无需手动挑选网关。支付方式名称可能相同，但处理付款的网关套件可能已更换

如果已经扣款，刷新后先核对原订单和充值记录，不要直接再付一次；仍未到账时保留订单号、付款时间、金额和凭证，提交 [付款问题服务单](/help/support#payment)
:::

### 虚拟货币充值 {#crypto-top-up}

虚拟货币充值需要按订单向指定网络的地址转账，不能只核对币种名称。下面以虚构 USDT 订单演示；可用币种和网络以收银台当次显示为准，不要求所有 USDT 订单都走同一条链

<figure class="guide-figure">
  <a href="/illustrations/account-crypto-top-up-zh.svg?v=20261105-3" target="_blank" rel="noopener" aria-label="核对虚拟货币订单再转账">
    <img src="/illustrations/account-crypto-top-up-zh.svg?v=20261105-3" alt="核对虚拟货币订单再转账" width="1120" height="975" loading="lazy">
  </a>
  <figcaption>界面示意 · 虚构数据 · 点击放大</figcaption>
</figure>

1. 选择收银台提供的虚拟货币方式；入口已注明网络时使用该网络，多币种入口则先选择币种，核对页面给出的网络、汇率和平台手续费
2. 输入要充值到账户的金额，核对 CNY／USD 并点击「创建订单」。账户充值金额与链上「需到账金额」不是同一单位；下单前的预计币数只作参考，实际转账使用已生成订单的币数
3. 核对订单的币种、**转账网络、收款地址、需到账金额和付款剩余时间**。在钱包或交易所选择完全一致的币种和网络，复制当次订单地址；地址二维码仅包含收款地址，扫描后仍要自行核对网络与金额
4. 按订单的金额规则转账。显示「到账金额需完全一致」时，保留全部小数位，不能自行取整；显示「到账金额不能少于此金额」时，到账需达到要求，多出部分不退还。不要把一个渠道的金额规则套用于所有渠道
5. 核对交易所提现手续费及最终到账金额。平台手续费与交易所／链上转账费用不同，无平台手续费不等于转账无费用；若交易所从提现数量中扣费，可用「提现手续费计算」按 **需到账金额 + 手续费** 计算，并以交易所最终显示的到账金额再次核对
6. 在订单有效期内转账一次并保留交易哈希。当前虚拟货币订单付款有效期为 60 分钟，以页面倒计时为准；未付款而已过期时重新创建订单，不再使用旧金额或旧地址
7. 返回收银台等待查询与链上确认，再到 [充值记录](https://oixcloud.com/user/code) 核对实际入账。钱包显示已发出、链上已确认与网站余额已入账是不同阶段

**已付款但未自动到账？** 在完整收银台下方的「虚拟币订单记录」点击「未到账反馈」，见 [入口示意图与处理步骤](#crypto-payment-feedback)

| 页面状态或问题 | 如何处理 |
| --- | --- |
| 正在重新连接 | 查询暂时中断，不代表付款失败；已付款时先核对原订单和充值记录 |
| 已检测到交易，尚未确认入账 | 等待链上确认；即使付款窗口结束，也不要再次转账或新建订单；检查记录，未到账按 [反馈步骤](#crypto-payment-feedback) 处理 |
| 少付、网络选错或付款超过有效期 | 保留原订单、交易哈希与凭证，按 [未到账反馈](#crypto-payment-feedback) 核查；不要自行追加转账或另建订单补救 |
| 充值成功 | 核对余额和套餐记录；不要再次付款 |

普通充值后仍需到 [套餐商店](https://oixcloud.com/user/shop) 完成购买；已有自动续费或自动重置流量时，资金可能按对应规则扣除，请同时核对 [套餐管理](https://oixcloud.com/user/bought)

已有充值码时，打开 [充值码与充值记录](https://oixcloud.com/user/code)，在「充值码」中输入完整代码，点击「使用充值码」，成功后核对记录和余额。充值码不是 Access Token、订阅地址或支付订单号

| 遇到的情况 | 处理方式 |
| --- | --- |

## 充值、购买与激活

### 选择套餐并确认购买 {#purchase}

    <img src="/illustrations/account-purchase-zh.svg?v=20261105-3" alt="选择计费周期后核对购买订单" width="1120" height="975" loading="lazy">
  </a>
  <figcaption>界面示意 · 虚构数据 · 点击放大</figcaption>
</figure>

1. 打开 [套餐商店](https://oixcloud.com/user/shop)，选择商品支持的计费周期，核对该周期的总流量、有效期、用途、库存和总价；「折合每月」是价格参考，不代表按月扣款或每月重置流量
2. 点击「购买」或「加购套餐」，在「确认购买」中核对套餐、周期与金额；有折扣代码时按 [用码步骤](#coupon-use) 先点「验证」，以验证后的实付金额为准。USD 仅供参考，订单确认与实际扣款以 CNY 为准
3. 阅读购买条款和页面提示，按要求完成勾选或文字确认，再提交购买；余额不足时按提示进入收银台补款，不要连续提交多个订单
4. 返回「套餐管理」，确认记录是「使用中」还是「待激活」，并核对剩余时间和流量；有当前套餐时，加购不会立即覆盖它

充值先增加余额，购买才生成套餐订单。当前没有套餐时，新购套餐可直接生效；已有套餐时，新购套餐进入待激活队列。按上方步骤购买后，在此确认当前生效套餐

### 从套餐购买进入收银台

余额不足时，购买流程可带着所选套餐进入收银台；支付到账后，系统会尝试使用账户资金完成原购买。页面显示充值成功时，仍需检查套餐管理中的实际记录，不能立即再买一次

若自动购买暂时失败，系统可能继续重试。收到「付款后自动购买未完成」且已停止重试的通知后，再核对余额并手动购买或联系支持；款项保留在账户中，已有欠款按充值规则抵扣。普通充值与这类带套餐的付款流程不同

### 已购买套餐与商店变化

已购买记录激活时，套餐类型按该记录保存的内容应用，普通套餐流量也取该记录的额度；按量套餐的可用流量仍按余额、佣金和当前单价折算。商店后来把同一商品改为按量或其他类型，不会因此把原普通套餐改成按量计费；新购买、续费或升级仍需核对当次确认页面的套餐与价格

## 折扣代码 {#coupons}

折扣代码用于套餐购买、适用的更换／升级或购买后绑定，不用于收银台充值，也不是充值码、注册邀请码或 Access Token。每次操作只填写一个代码，不叠加多个折扣；保留原代码的大小写，完整复制后按当次套餐、计费周期和操作验证

系统代码可能限制生效时间、套餐、周期、用户资格、使用场景、总次数和每人次数；能用于新购，不代表也能用于升级或购买后绑定。本人生成的代码可在 [权益中心](https://oixcloud.com/user/benefits) 的「我的折扣代码」复制，当前生成的是一次性代码，限本人或尚无购买记录的新用户使用；生成会消耗页面显示的权益额度且不能撤销，已使用的代码不能再用

### 购买时使用 {#coupon-use}

<figure class="guide-figure">
  <a href="/illustrations/account-coupon-use-zh.svg?v=20261105-6" target="_blank" rel="noopener" aria-label="购买时验证折扣并核对续费报价">
    <img src="/illustrations/account-coupon-use-zh.svg?v=20261105-6" alt="购买时验证折扣并核对续费报价" width="1120" height="975" loading="lazy">
  </a>
  <figcaption>界面示意 · 虚构金额，示例折扣代码不可使用 · 点击放大</figcaption>
</figure>

1. 在 [套餐商店](https://oixcloud.com/user/shop) 先选套餐及计费周期，打开「确认购买」，在「折扣代码」中输入代码并点「验证」
2. 核对是否验证成功、折扣幅度、「一次性折扣代码」或「循环折扣代码」、实付金额，以及页面显示的续费报价或不提供续费提示。**20% 折扣表示减免 20%，即支付原价的 80%（八折）**，不是支付 20%
3. 改了代码、套餐或周期后重新验证；验证只提供本次报价，不会购买套餐、预留使用次数或自动完成付款。提交时仍会检查代码是否可用
4. 确认金额后按 [购买步骤](#purchase) 完成条款确认与支付，再核对套餐记录和余额。一次性折扣只影响本次购买，不让后续续费自动同折；循环折扣也不会自动开启续费

新购的最终金额会按页面规则取整；升级、购买后绑定和循环续费的计价规则不同，不要直接用一个折扣百分比推算所有操作，下面分别说明

### 购买后绑定折扣 {#bind-coupon}

<figure class="guide-figure">
  <a href="/illustrations/account-coupon-bind-zh.svg?v=20261105-6" target="_blank" rel="noopener" aria-label="购买后绑定前核对补退差价">
    <img src="/illustrations/account-coupon-bind-zh.svg?v=20261105-6" alt="购买后绑定前核对补退差价" width="1120" height="975" loading="lazy">
  </a>
  <figcaption>界面示意 · 虚构金额，示例折扣代码不可使用 · 点击放大</figcaption>
</figure>

**绑定会立即结算本期差价，可能退回余额，也可能补扣余额**。通常仅首次购买后 7 天内、仍为「使用中」或「待激活」且有实付金额的记录提供「绑定折扣」；升级不会重新计算这 7 天。特殊转换记录不支持；已单独获准一次超期绑定的，以页面入口为准，成功后这次许可即用完

1. 打开 [套餐管理](https://oixcloud.com/user/bought)，核对原购买记录，点击「绑定折扣」进入「绑定折扣代码」窗口
2. 输入适用于购买后绑定的系统代码，或本人生成且未使用的代码，点击「验证」；不要用他人生成的新用户代码给已有套餐补绑
3. 核对「折扣后价格」和「退还差价」或「应补差价」，并检查代码类型与续费报价。差价按当前套餐对应周期的折后价与记录原价比较，再按剩余时长结算；使用中套餐不退整期差额。当前补绑折后价格不低于该周期当前售价的 70%，还会按规则取整；因此晚绑的金额不一定等于购买时直接用码
4. 接受补退金额及续费影响后点「确认绑定」。需要补扣时先保证资金足够；改代码或提示报价变化后重新验证。无差价且不是循环代码时，会提示绑定不产生变化，不会据此消耗代码
5. 成功后核对余额、该记录的续费信息及代码使用状态。绑定不会延长有效期、增加或重置流量，也不会自动打开续费开关；一次性绑定后，「折扣代码」列可能仍显示原循环代码或空白，以结算结果为准

**若一次性代码只产生补款，请取消操作**：它不会改善续费权益。已有循环优惠不需要反复绑定；不要为了“保留优惠”重新提交相同代码，以免额外消耗使用次数

这与 [退款至余额](#refund) 不同：绑定仅结算折扣差价，套餐继续保留；成功使用后代码的使用次数会被消耗，套餐退款也不会恢复已用代码

### 循环折扣与续费 {#recurring-coupon}

<figure class="guide-figure">
  <a href="/illustrations/account-coupon-recurring-zh.svg?v=20261105-6" target="_blank" rel="noopener" aria-label="核对循环代码与自动续费设置">
    <img src="/illustrations/account-coupon-recurring-zh.svg?v=20261105-6" alt="核对循环代码与自动续费设置" width="1120" height="975" loading="lazy">
  </a>
  <figcaption>界面示意 · 虚构金额，示例折扣代码不可使用 · 点击放大</figcaption>
</figure>

「循环」表示成功应用后的优惠可由对应购买记录沿用，**不表示可以无限次重新输入代码，也不表示永久固定金额或自动开启续费**。购买或绑定后，按 [自动续费步骤](#auto-renew) 选择要续的记录并核对开关；待激活队列、到期时间、资金与续费资格仍按原规则处理

| 操作 | 对续费优惠的影响 |
| --- | --- |
| 新购使用一次性代码 | 优惠只用于本次购买，续费按当次显示的常规续费价 |
| 新购使用循环代码 | 保存对应优惠与续费价，新购的自动续费仍默认关闭 |
| 给已有记录绑定一次性代码 | 只结算本期差价，原续费价和已有循环优惠保持不变 |
| 给已有记录绑定循环代码 | 结算本期差价，并用这次代码更新该记录的循环优惠与续费价，不与原折扣叠加；续费开关保持原设置 |
| 更换／升级时留空代码 | 尝试继承原循环优惠，仍须适用于目标套餐及周期；无法继承时按提示处理 |
| 更换／升级时主动填写新代码 | 按新代码重新报价与设置续费优惠；若新代码是一次性的，原循环优惠不会继续保留，应在确认前核对续费价 |

循环续费报价不低于对应周期售价的 70%，新购优惠后的实付可能低于这个续费金额。当前这次自动续费按原记录的续费价扣款；续上后，下一期续费价还可能按当时套餐售价的 70% 下限调整，请核对新记录，不把首次报价理解为永久锁价

代码过期、停用或次数耗尽会影响再次主动使用；已记录循环优惠的续费不需要每期重新输入代码。原套餐续费与把优惠继承到另一个套餐是不同操作，升级预览失败也不等于原续费价已改变。自动重置流量不享折扣代码

### 验证失败或金额不符

| 提示或现象 | 先检查 |
| --- | --- |
| 不存在、尚未生效、过期、停用或次数不足 | 代码大小写、有效时间和可用次数；不要连续重复验证 |
| 不适用于套餐、周期或本次操作 | 当前选中的套餐、计费周期，以及这是购买、升级还是购买后绑定 |
| 仅限新用户／特定用户 | 账户是否已有购买记录，是否满足代码资格；本人生成代码与他人分享代码的条件不同 |
| 没有「绑定折扣」入口 | 原购买时间、记录状态、实付金额与特殊记录限制；不要为了刷新期限而升级 |
| 绑定需要补款或报价变化 | 按新的补退方向和金额重新核对，不把「绑定折扣」当作必定退款 |
| 已绑定一次性代码，但续费价没变 | 这是预期行为；一次性绑定只结算本期差价，循环代码才更新续费优惠 |

结果不明时先核对余额、套餐记录与页面提示，再提供记录信息和错误原文提交 [服务单](/help/support#payment)，不要重复购买或绑定

## 售罄与自动补货 {#stock}

部分套餐实行限量销售，显示「售罄」时当前没有可供新购的库存。**我们通常不会手动补货**，可购买名额主要等已有套餐到期、退款或转到其他套餐后自动回补，没有固定补货时间或数量

停止续费与释放库存之间有时间差：用户关闭自动续费后，原套餐仍可使用到期；到期后没有续费、也没有可接续的待激活套餐，系统完成套餐终止时，才返还对应库存。用户在这种已过期且没有可接续套餐的状态下重新购买，购买流程也会先清理旧的过期生效记录并返还其库存

**每条待激活、生效中，或被接替后排在其他套餐之后的购买记录均占用 1 份库存**，记录结束或转到其他套餐时归还；原套餐保留剩余权益回到待激活队列，或转为「等待自动续费」时，仍继续占用。具体变化如下：

| 操作或状态 | 库存如何变化 |
| --- | --- |
| 新购套餐（含提前加购） | 对应套餐库存减 1；即使进入待激活队列，也在购买时占用 |
| 正常自动续费 | 新一期接续原记录占用的库存，不再扣减也不返还；仍须满足余额、续费资格等条件 |
| 关闭自动续费 | 当时不返还；需等符合条件的到期终止或清理 |
| 到期或流量用完时自动接续待激活套餐 | 接续的套餐已在购买时扣减，不重复扣减；被换下的原套餐若开着自动续费则转为「等待自动续费」并继续占用，否则直接结束并返还 1 份 |
| 手动激活待激活套餐 | 原套餐满足保留条件时回到待激活队列并继续占用；不足以保留时，开着自动续费的转为「等待自动续费」并继续占用，其余结束并返还 1 份 |
| 等待自动续费的套餐续上 | 新一期接续它占用的库存，不再扣减 |
| 升级或更换套餐 | 目标套餐按购买扣减，原套餐返还 1 份 |
| 符合条件的退款至余额 | 返还 1 份 |
| 到期且未续费、无可接续套餐，系统完成终止／清理 | 返还对应的有限库存，排在其他套餐之后而没续上的一并返还 |

因此，新购页面售罄不等于已有用户无法正常自动续费；**提前加购仍按新购检查库存和价格**，不能与正常自动续费混为一谈。库存恢复也不会自动把已下架商品重新上架

稍后刷新商店查看实际可购买状态，或选择其他在售套餐。充值、打开收银台和提交未付款订单不会预留套餐库存，购买完成前库存仍可能变化；请勿仅为等待补货反复充值或关闭现有自动续费

## 套餐临界值与使用范围 {#threshold}

购买时除流量、期限和速率外，还要核对「临界值」与个人／团队用途。临界值是公平使用积分的计算倍率，既不是允许登录的设备数，也不是多人共享许可；各设备与节点的活动按同一账户合并计算

具体请求档位、Working nodes 档位、闲时时间和恢复条件见 [公平使用](/account/fair-use)。购买新套餐进入待激活队列时，不能把新套餐的限制提前当作当前账户的限制

### 自动续费 {#auto-renew}

<figure class="guide-figure">
  <a href="/illustrations/account-renewal-zh.svg?v=20261105-3" target="_blank" rel="noopener" aria-label="核对自动续费对象和续费价格">
    <img src="/illustrations/account-renewal-zh.svg?v=20261105-3" alt="核对自动续费对象和续费价格" width="1120" height="975" loading="lazy">
  </a>
  <figcaption>界面示意 · 虚构数据 · 点击放大</figcaption>
</figure>

1. 打开 [套餐管理](https://oixcloud.com/user/bought)，找到希望到期后续上的记录，点击它的「自动续费」开关
2. 在确认框核对续费价格，以及是否会关闭另一份套餐的自动续费，再确认操作
3. 保存后核对该记录的开关和「续费价格」，并在到期前准备足够余额（含佣金）；开启开关本身不会立即购买下一期
4. 到期处理后，检查新的使用中记录、有效期与流量，不要只凭开关已开启判断续费成功

当前不提供单独的「提前续费」操作。若要提前准备下一期，请从商店加购，并比较当次新购价与原记录的续费价；两者可能不同

同一时间只有一份套餐开着自动续费。当前生效套餐到期、且没有可接续的待激活套餐时，系统才尝试续这一份；当前套餐仅流量用完而尚未到期时，不会触发自动续费。新购的套餐不开自动续费，需要时在购买记录里开启；在另一条购买记录上开启自动续费，原来开着的那份随之关闭

自动续费可以随时开关。关闭不会放弃原续费价格，在这份套餐结束前随时可以重新开启；开启需要商品支持自动续费，账户也仍符合该套餐的购买条件

开着自动续费的套餐被待激活套餐接替时，转为「等待自动续费」：它不再使用，排在其他套餐之后，继续占用名额；等当前生效套餐到期、且没有可接续的待激活套餐时，满足续费资格、计费周期和资金条件的，按该记录的续费价续上新一期；余额不足或已无续费资格的随之结束。关掉它的自动续费后不再显示这个状态，当前生效套餐到期且没有可接续套餐时结束；在那之前重新开启，仍可按条件续上

例如：A 开着自动续费并处于等待状态，B 正在使用，队列中没有其他套餐。B 提前用完流量时，先按 B 的设置尝试自动重置，否则保持低速；直到 B 到期，才尝试自动续费 A

### 自动重置流量 {#traffic-reset}

<figure class="guide-figure">
  <a href="/illustrations/account-traffic-reset-zh.svg?v=20261105-3" target="_blank" rel="noopener" aria-label="开启自动重置前核对每次费用">
    <img src="/illustrations/account-traffic-reset-zh.svg?v=20261105-3" alt="开启自动重置前核对每次费用" width="1120" height="975" loading="lazy">
  </a>
  <figcaption>界面示意 · 虚构数据 · 点击放大</figcaption>
</figure>

1. 打开 [套餐管理](https://oixcloud.com/user/bought)，在目标记录中找到「自动重置流量」，核对开关下方的每次费用；待激活记录的设置在激活后才适用
2. 点击开关并阅读确认框。当前流量已经用完且满足立即处理条件时，会提示「开启并扣款」，确认后约 1 分钟内可能发生扣款
3. 重置后刷新用户中心，核对已用流量清零、余额扣减和到期时间不变；若连接仍慢，等待节点同步后重新连接
4. 不希望以后继续自动付费重置时，关闭该记录的开关；这不会关闭自动续费，也不会取消已经完成的重置扣款

可在购买记录里为每条记录单独开启「自动重置流量」，默认关闭，续费生成的新记录沿用原记录的设置。开启后，当前套餐尚未到期、流量用完且没有可接续的待激活套餐，本期支持重置、账户允许购买并且资金足够时，系统按重置价清零已用流量，到期时间不变；重置价显示在购买记录的开关下方，不享折扣代码；它按当前商品对应周期的重置价计算，未单独设置时使用该周期当前售价，不是原记录的续费价

流量已用完时再开启，满足上述条件的约 1 分钟内扣款并重置；仅因余额（含佣金）不足而未重置的，保持低速，充值补足后自动重置。到期前任何时候用完，满足条件都可重置；临近到期重置不会延长有效期，到期后仍先检查待激活队列，没有可接续套餐时才按自动续费设置处理。开发者套餐与按量付费套餐不提供

自动重置不是一次性购买：开关保持开启时，同一期再次耗尽流量且条件满足，仍会再次按重置价扣款。本期付费重置后不发放到期权益额度，见 [权益额度发放](#benefit-credits)

## 权益额度发放 {#benefit-credits}

Pass Gold 及以上年付套餐（含按量付费）在自然到期时发放权益额度，开发者账户不参与：

| 套餐到期时的情况 | 发放额度 |
| --- | --- |
| 普通套餐，剩余流量大于 0 且不足 50% | 5 枚 |
| 普通套餐，剩余流量至少 50% | 10 枚 |
| 普通套餐，流量已耗尽 | 不发放 |
| 符合上述条件的按量付费套餐 | 固定 5 枚 |

**普通套餐流量用尽后不发放权益额度，低速使用至到期也不补发；本期付费重置过流量的套餐同样不发放**。续费或切换后的新套餐按上述条件单独计算；提前结束、退款或尚未激活的套餐不发放

可在 [权益中心](https://oixcloud.com/user/benefits) 查看可用额度与兑换项目

## 升级与提前使用下一份套餐

季付、半年付和年付套餐均可按条件升级或更换，月付不支持。目标套餐须支持原计费周期，操作后保留该周期，例如季付升级后仍为季付

| 当前套餐状态 | 升级或更换条件 |
| --- | --- |
| 使用中 | 只能升级到更高等级，且按系统计算的剩余天数至少为 60 天 |
| 从未使用的待激活套餐 | 可按页面条件更换，完成后仍为待激活，不立即替换当前套餐 |
| 曾使用、现处于待激活状态 | 不能直接更换或升级，需先激活后再核对升级资格；先阅读下方切换损耗 |

目标还须满足购买资格、库存和资金条件；转换过的特殊记录可能不提供更换／升级入口。请在完整网站的「套餐管理」操作，以该记录实际显示的按钮与可选目标为准

1. 打开 [套餐管理](https://oixcloud.com/user/bought)，核对要操作的原记录，使用中的点「升级」，从未使用的待激活记录点「更换」
2. 在「更换/升级」窗口选择目标套餐，核对计费周期。可填写折扣代码并点「验证」；留空时会尝试继承原订单的循环折扣，但仍须适用于目标套餐及周期，不是无条件保留；填写新代码前请核对 [对原循环折扣的影响](#recurring-coupon)
3. 等预览完成，核对「实际支付金额」、折扣及续费价格；普通套餐升级还应检查「升级后剩余高速流量」与「流量净变化」。余额不足先补足，目标或金额变化后重新核对，不沿用旧报价
4. 确认能接受下述费用与流量变化后，点击「确认更换/升级」。完成后检查原购买记录中的目标套餐、状态、剩余流量、到期时间和续费设置；使用中的套餐变更后刷新客户端账户信息与托管配置

**使用中套餐的升级不是重新购买一整期**：按剩余天数比例计算差价并计入手续费，实付最低为 0，不会因折扣后的目标价格更低而退钱。普通套餐升级为普通套餐时，到期时间不变、已用流量保留，新剩余额度为目标周期额度减去已用量（最低为 0），不是目标套餐的全额流量；预览与最终结果可能因期间继续用量而略有变化。涉及按量付费时按目标套餐计费规则处理，不套用普通套餐的流量公式

**从未使用的待激活套餐更换**按完整周期计算差价，不收上述升级手续费；差价为正时补款，为负时退至账户余额，记录继续待激活

操作后续费价格按目标套餐与适用折扣重算。原来开启自动续费且目标支持时继续开启；目标不支持时关闭，原来关闭的不会因此自动开启。完成后同时核对自动重置流量的可用状态与每次费用

## 手动激活与退款至余额

这两项都从购买记录操作：激活会立即切换当前套餐；退款会结束被退的记录。请先核对记录与确认框，不把它们当作续费或充值

### 手动激活 {#manual-activation}

<figure class="guide-figure">
  <a href="/illustrations/account-activation-zh.svg?v=20261105-5" target="_blank" rel="noopener" aria-label="手动激活前确认原套餐去向">
    <img src="/illustrations/account-activation-zh.svg?v=20261105-5" alt="手动激活前确认原套餐去向" width="1120" height="975" loading="lazy">
  </a>
  <figcaption>界面示意 · 虚构套餐与数值 · 点击放大</figcaption>
</figure>

**已有使用中套餐时，每次手动切换都会从原套餐扣除 2 小时有效时间**，剩余时间按整分钟、普通套餐剩余流量按整 GiB 向下保存。原套餐能保留时转为待激活；不足以保留时，开着自动续费的转为「等待自动续费」，其余直接结束。重复切换会再次产生损耗；结束的记录不能靠切回恢复

1. 打开 [套餐管理](https://oixcloud.com/user/bought)，在要立即使用的待激活记录上点击「激活」；手动激活要求至少剩余 6 小时且有可用流量，按量付费套餐不要求预存流量额度
2. 阅读「提示」窗口，确认原套餐会变为待激活、等待自动续费还是直接结束；图中仅演示可以保留的情况。没有使用中套餐时不涉及换下原套餐，也不扣这笔切换损耗
3. 决定立即使用后点「确认切换」，否则点「再想想」。激活不合并两份套餐的流量或期限，新套餐从激活时起按该记录剩余时长计时
4. 完成后核对新记录为「使用中」、原记录去向及剩余时间／流量，刷新客户端账户信息与托管配置；自动续费对象不会仅因激活另一份而自动改选，需要时另行设置

剩余不足 6 小时的待激活套餐没有手动激活入口；仍有有效时长与可用流量的，可在当前套餐到期或流量耗尽时按队列自动接续。若页面提示无法切换，按具体原因处理，不要反复购买来代替激活

### 退款至余额 {#refund}

<figure class="guide-figure">
  <a href="/illustrations/account-refund-zh.svg?v=20261105-5" target="_blank" rel="noopener" aria-label="退款前确认金额与套餐结束">
    <img src="/illustrations/account-refund-zh.svg?v=20261105-5" alt="退款前确认金额与套餐结束" width="1120" height="975" loading="lazy">
  </a>
  <figcaption>界面示意 · 虚构套餐与数值 · 点击放大</figcaption>
</figure>

**退款会结束这份套餐，款项仅退到账户余额，不退到原支付渠道，也不是提现；已使用的折扣代码不退还**。自助入口仅支持符合条件、有可退实付金额且从未使用的待激活记录：年付，以及页面提供入口的特定季付套餐；不是所有季付都支持，月付和半年付不提供该自助退款。曾使用后切回待激活也不符合条件

1. 在 [套餐管理](https://oixcloud.com/user/bought) 找到原记录，核对套餐名称、周期和「待激活」状态，点击「退款至余额」
2. 在「请确认」窗口核对本次退回金额与结束套餐的后果。金额按该记录的实际已付金额核算，已发生的补款或差额退款也会影响它，不按商店现价或续费价退款
3. 确认后点击「确定」，不退款则点「取消」。若提示金额或状态变化，刷新记录后重新核对
4. 完成后核对账户余额与「已退款」状态；该记录不再能激活或续费，当前正在使用的其他套餐不会因这笔待激活记录退款而结束

未显示入口时先检查周期、是否曾使用及记录状态；不要先激活来尝试获得退款资格。若操作结果不明，刷新余额与记录并保留提示，按 [付款与套餐问题](/help/support#payment) 提供资料核查，不重复提交

## 按目的选择操作

| 你想做什么 | 应选择什么 | 完成后核对 |
| --- | --- | --- |
| 首次开通服务 | 选择套餐购买，按提示补款 | 套餐管理出现生效记录，用户中心显示等级、有效期和额度 |
| 提前准备下一期 | 从商店加购套餐 | 下一份出现在待激活队列，当前流量不会立即增加 |
| 立即使用下一份 | 手动激活待激活套餐 | 先看旧套餐扣减和保留预览，再检查新生效记录 |
| 流量耗尽时自动恢复高速 | 开启自动重置流量 | 在购买记录中开启，核对重置价与账户余额 |
| 调高当前季付、半年付或年付等级 | 符合条件时使用升级入口，保留原计费周期 | 核对差价、手续费、剩余有效期和升级后额度 |
| 当前套餐到期且队列为空时改续另一份套餐 | 在那条购买记录上开启自动续费 | 原来开着的那份随之关闭，确认框写明会替代哪一份 |
| 不再自动扣款续期 | 关闭自动续费 | 购买记录里该套餐的自动续费显示为关闭；之后需要时可重新开启，续费价不变 |

## 购买后如何确认

按 [购买步骤](#purchase) 完成后，先核对「套餐管理」的记录状态、剩余时间与流量。新套餐生效后刷新客户端账户信息与托管配置，确认节点权限更新；不要因待激活套餐尚未增加当前额度而重复购买

如果支付平台已扣款但页面没有成功结果，先核对充值记录和套餐记录，保留订单号及时间再联系支持；充值到账与套餐购买是两个状态，购买流程中的自动处理也需分别确认

## 虚拟货币充值未到账 {#crypto-payment-feedback}

打开完整的 [收银台页面](https://oixcloud.com/user/v2/counter)，向下找到付款区域下方的「**虚拟币订单记录**」，在原订单的「操作」列点击「**未到账反馈**」。嵌入式付款弹窗不显示这块记录，找不到时请打开完整页面

<figure class="guide-figure">
  <a href="/illustrations/account-crypto-feedback-zh.svg?v=20261105-4" target="_blank" rel="noopener" aria-label="找到未到账反馈按钮并提交原交易">
    <img src="/illustrations/account-crypto-feedback-zh.svg?v=20261105-4" alt="找到未到账反馈按钮并提交原交易" width="1120" height="975" loading="lazy">
  </a>
  <figcaption>界面示意 · 虚构订单与哈希占位符 · 点击放大</figcaption>
</figure>

1. 核对原订单号、创建时间和金额；已经付款的不要重复支付或删除。列表显示近 48 小时未入账的订单，以及更早但仍在自动核查、待用户确认或人工审核中的反馈；已到账的到 [充值记录](https://oixcloud.com/user/code) 核对
2. 创建未满 5 分钟时，按钮显示「等待自动入账」，点击会重新打开原付款订单；满 5 分钟后，符合条件的记录显示「未到账反馈」。首次反馈须在创建后 48 小时内提交；已进入处理中的反馈不会仅因超过该期限而消失
3. 在「未到账反馈」窗口填写完整的「交易哈希值」，可在「问题描述」补充实际付款时间、转账网络及问题，再点击「提交」。TRC20 哈希为 64 位十六进制；Polygon／BSC 为 `0x` 开头的 66 位十六进制。交易哈希不是订单号、钱包地址或私钥；已自动填入且不能修改时，继续处理这份原反馈
4. 按返回状态操作：「自动核查中」或「人工审核中」时等待，不反复提交；「等待您确认」时重新点击该操作入口，核对拟入账金额后决定是否确认；「核实后重新提交」时按说明检查哈希与付款资料。已关联交易的订单也可能显示「重试反馈通知」，按提示继续，不要另建订单
5. 返回充值记录确认实际到账，再到「套餐管理」检查购买／激活结果。反馈提交成功、进入审核或订单从这张列表消失，都不能单独证明到账或套餐生效

没有入口、超过首次反馈时限或结果持续不明时，按 [付款问题服务单](/help/support#payment) 提交原订单资料与页面提示。不要提供钱包私钥、助记词或验证码

## 自动接续没有发生

核对耗尽原因并分别检查对应的接续条件：

- **套餐到期时**：优先检查待激活队列中是否有可激活套餐；没有待激活套餐时，才续开着自动续费的那一份（可能是当前套餐，也可能是等待自动续费的套餐），需核对它的自动续费是否开启、账户余额（含佣金）是否足够支付它的续费价，以及续费资格和计费周期是否有效
- **流量用尽时**：优先检查待激活队列中是否有可激活套餐；没有待激活套餐时，检查当前购买记录是否开启了「自动重置流量」、本期是否支持重置、账户是否允许购买，以及余额（含佣金）是否足够支付重置价。注意自动续费只在套餐到期时执行，流量用完不会提前触发自动续费

手动激活、升级和退款入口按订单状态显示；没有入口时不要用新建订单模拟同一操作
