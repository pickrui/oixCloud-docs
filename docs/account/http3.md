# HTTP/3 与智能回退

HTTP/3 基于 QUIC（UDP），这里用于客户端与节点之间的 Hollow 连接，目标网站无需支持 HTTP/3。默认使用 TCP，建议先在一个常用节点上尝试，并保留智能回退

## 适用范围 {#scope}

仅支持此功能的官方客户端 Hollow 连接会读取这项设置，AnyTLS 连接及不支持该功能的客户端不受影响。使用 [软件中心](https://oixcloud.com/client) 提供的对应客户端，并以当前版本与实际连接协议为准，不要仅凭客户端名称认定 HTTP/3 已生效

| 页面中的节点项 | 设置范围 |
| --- | --- |
| 普通节点 | 同一逻辑节点的同名后端一起设置 |
| 独享 IP | 按当前账户的具体地址分别设置，同节点上的其他独享 IP 不受影响 |
| 标记为暂不支持流量路由 | 不能修改；手动加入订阅不会解除限制 |

未默认下发的 Home ISP 也受 [流量路由限制](/account/nodes#isp-routing) 约束。可配置范围以页面列表为准

1. 打开用户中心的「流量路由 → [HTTP/3](https://oixcloud.com/user/http3)」，搜索节点名称或独享 IP 地址
2. 打开对应行的「启用 HTTP/3」，先保留「智能回退」开启。独享 IP 需核对行内完整地址
3. 开关自动提交，等待保存成功；**随后在客户端更新订阅或托管配置，并等待更新完成**
4. 选择该节点，关闭目标应用的旧连接后重新连接，使用同一网站或应用验证实际体验。共用此账户的其他设备也需更新各自的配置后才会采用新设置

关闭 HTTP/3 或调整智能回退后，也要更新客户端订阅并建立新连接。页面显示的是已保存的传输策略，不是客户端此刻实际使用的传输方式

## 三种传输状态与智能回退 {#fallback}

| 启用 HTTP/3 | 智能回退 | 新连接的行为 |
| --- | --- | --- |
| 关闭 | 不生效，开关不可操作 | 使用 TCP |
| 开启 | 开启 | 优先尝试 HTTP/3；连接较慢时也尝试 TCP，使用先建立成功的连接 |
| 开启 | 关闭 | 只使用 HTTP/3，失败时不能改用 TCP |

开启智能回退时，HTTP/3 失败后，客户端会暂缓重试，期间使用 TCP；之后再尝试 HTTP/3。因此，即使页面显示「HTTP/3（智能回退）」，实际连接仍可能使用 TCP

智能回退只在建立连接时选择传输方式，**不会因为下载速度慢而切换，也不会把已经建立的连接迁移到另一种传输方式**。关闭回退前，应确认当前网络能够稳定使用 UDP

## 多节点批量设置 {#bulk-settings}

列表不分页，可搜索名称或地址，并按「已开启」「未开启」等状态筛选；手机上可横向滑动顶部分类栏

1. 勾选目标节点，或点「全选」选中当前搜索与筛选条件下的全部可用项，包括屏幕下方的行。修改搜索或筛选条件会清空选择
2. 选择「开启所选」「关闭所选」「开启智能回退」或「关闭智能回退」，核对「应用到 N 个节点」后执行
3. 智能回退只修改已经开启 HTTP/3 的节点；不可用项和状态已相同的项会跳过，所以应用数量可能少于已选数量。独享 IP 按每一行的地址分别处理
4. 等待结果，再更新客户端订阅并重新连接

批量操作逐个保存，后续失败不会撤销已经成功的设置。遇到超时或中断时，按页面的已确认保存、未确认成功和未尝试数量核对；先刷新页面，再重试仍需修改的项

## 与 WARP、IPv4 Only 和中继一起使用 {#other-settings}

HTTP/3 调整客户端到节点的传输，WARP 调整节点访问网站的出口路径，[IPv4 Only](/account/unlock#ipv4-only) 限制目标网站连接的地址族。这些设置可以配合使用，HTTP/3 本身不决定网站看到 IPv4 还是 IPv6

两种「智能回退」的作用不同：HTTP/3 回退到同一节点的 TCP 传输；[WARP 回退](/account/unlock#warp-ip-preference) 改用远程节点的普通出口，网站看到的 IP 或地区可能改变。两者分别设置

HTTP/3 开关本身不删除中继规则，也不修改 WARP 或 IPv4 Only 设置。有 [内部中继](/account/relay) 时，此项仍用于客户端连接入口节点，不会把整条中继路径都改为 HTTP/3；客户端策略组或代理链应核对最终选中的节点和配置

## 性能与使用建议 {#performance}

HTTP/3 可能减少连接建立的等待，并减轻丢包时不同数据流之间的相互阻塞，在高延迟或有一定丢包的线路上可能更流畅，但不保证比 TCP 更快

UDP 线路质量、运营商或公司／校园网络的 UDP 限制，以及设备处理开销，都可能造成超时、速度下降或波动。保留智能回退能够在建立连接时尝试 TCP，并不保证所有网络都能连接

先在同一网络、同一节点、同一目标下对比连接成功率、延迟和实际传输体验。若持续变慢或不稳定，关闭 HTTP/3、更新订阅并重新连接，再做同条件对照；不要同时调整 WARP、出口协议和客户端规则，以免无法判断原因

## 常见问题 {#troubleshooting}

| 现象 | 核对方式 |
| --- | --- |
| 已保存，但客户端仍使用 TCP | 先更新订阅并建立新连接；确认使用支持 HTTP/3 的 Hollow 连接，且智能回退没有选择 TCP |
| 关闭智能回退后无法连接 | 检查当前网络的 UDP 连通性；重新开启回退或关闭 HTTP/3，再更新订阅重试 |
| 某个独享 IP 没有变化 | 核对设置行和客户端实际使用的完整地址，每个地址分别保存 |
| 下载变慢却没有自动切到 TCP | 回退只处理连接建立，不能按下载速度切换现有连接；关闭 HTTP/3 后更新订阅并重连对照 |
| 网站显示支持 HTTP/3，但无法判断节点是否生效 | 网站自身使用的 HTTP 版本与客户端到节点的传输是两段连接，不能相互证明 |

仍有问题时，通过 [服务单](/help/support) 提供客户端与版本、网络环境、节点名称或独享 IP、两个开关的状态、配置更新时间和具体报错；不要提供密码、Access Token 或完整订阅链接
