# HTTP/3 与智能回退

HTTP/3 基于 QUIC（UDP），这里用于客户端与节点之间的 Hollow 连接，目标网站无需支持 HTTP/3。默认关闭，建议先在一个常用节点上选择「智能回退」。无论选哪一项，UDP 流量都照常转发

## 适用范围 {#scope}

仅支持此功能的官方客户端 Hollow 连接会读取这项设置，AnyTLS 连接及不支持该功能的客户端不受影响。使用 [软件中心](https://oixcloud.com/client) 提供的对应客户端，并以当前版本与实际连接协议为准，不要仅凭客户端名称认定 HTTP/3 已生效

| 页面中的节点项 | 设置范围 |
| --- | --- |
| 普通节点 | 同一逻辑节点的同名后端一起设置 |
| 独享 IP | 按当前账户的具体地址分别设置，同节点上的其他独享 IP 不受影响 |
| 标记为暂不支持流量路由 | 不能修改；手动加入订阅不会解除限制 |
| 已选择 [CDN](#cdn) 的节点 | 支持 CDN 的官方客户端改走 AnyTLS，这里的设置不使用；页面会在该行提示 |

未默认下发的 Home ISP 也受 [流量路由限制](/account/nodes#isp-routing) 约束。可配置范围以页面列表为准

1. 打开用户中心的「流量路由 → 协议 → [Hollow](https://oixcloud.com/user/http3)」，搜索节点名称或独享 IP 地址
2. 在对应行选择「智能回退」。独享 IP 需核对行内完整地址
3. 选择后自动提交，等待保存成功；**随后在客户端更新订阅或托管配置，并等待更新完成**
4. 选择该节点，关闭目标应用的旧连接后重新连接，使用同一网站或应用验证实际体验。共用此账户的其他设备也需更新各自的配置后才会采用新设置

改选其他选项后，也要更新客户端订阅并建立新连接。页面显示的是已保存的设置，不是客户端此刻实际使用的连接方式

## 三个选项与智能回退 {#fallback}

| 页面选项 | 新连接的行为 |
| --- | --- |
| 关闭 | 不使用 HTTP/3，使用普通连接 |
| 智能回退 | 优先尝试 HTTP/3；连接较慢时也尝试普通连接，使用先建立成功的连接 |
| 仅 HTTP/3 | 只使用 HTTP/3，失败时不能改用普通连接 |

普通连接基于 TCP，同样能转发 UDP 流量。这里的选项只决定客户端到节点这一段怎么连，不影响 UDP 转发

选择智能回退时，HTTP/3 失败后，客户端会暂缓重试，期间使用普通连接；之后再尝试 HTTP/3。因此，即使页面选的是「智能回退」，实际连接仍可能没有使用 HTTP/3

智能回退只在建立连接时选择连接方式，**不会因为下载速度慢而切换，也不会迁移已经建立的连接**。选择「仅 HTTP/3」前，应确认当前网络能够稳定使用 UDP

## 多节点批量设置 {#bulk-settings}

列表不分页，可搜索名称或地址，并按「已开启」「未开启」等状态筛选

1. 勾选目标节点，或勾选表头的复选框选中当前搜索与筛选条件下的全部可用项，包括屏幕下方的行。修改搜索或筛选条件会清空选择
2. 在表头的批量操作里选择「关闭」「智能回退」或「仅 HTTP/3」，核对「应用到 N 个节点」后执行
3. 不可用项和选项已相同的项会跳过，所以应用数量可能少于已选数量。独享 IP 按每一行的地址分别处理
4. 等待结果，再更新客户端订阅并重新连接

批量操作逐个保存，后续失败不会撤销已经成功的设置。遇到超时或中断时，按页面的已确认保存、未确认成功和未尝试数量核对；先刷新页面，再重试仍需修改的项

## 与 WARP、IPv4 Only 和中继一起使用 {#other-settings}

HTTP/3 调整客户端到节点的传输，WARP 调整节点访问网站的出口路径，[IPv4 Only](/account/unlock#ipv4-only) 限制目标网站连接的地址族。这些设置可以配合使用，HTTP/3 本身不决定网站看到 IPv4 还是 IPv6

两种「智能回退」的作用不同：HTTP/3 回退到同一节点的普通连接；[WARP 回退](/account/unlock#warp-ip-preference) 改用远程节点的普通出口，网站看到的 IP 或地区可能改变。两者分别设置

这项设置本身不删除中继规则，也不修改 WARP 或 IPv4 Only 设置。有 [内部中继](/account/relay) 时，此项仍用于客户端连接入口节点，不会把整条中继路径都改为 HTTP/3；客户端策略组或代理链应核对最终选中的节点和配置

## 性能与使用建议 {#performance}

HTTP/3 可能减少连接建立的等待，并减轻丢包时不同数据流之间的相互阻塞，在高延迟或有一定丢包的线路上可能更流畅，但不保证比普通连接更快

UDP 线路质量、运营商或公司／校园网络的 UDP 限制，以及设备处理开销，都可能造成超时、速度下降或波动。选择智能回退能够在建立连接时尝试普通连接，并不保证所有网络都能连接

先在同一网络、同一节点、同一目标下对比连接成功率、延迟和实际传输体验。若持续变慢或不稳定，改回「关闭」、更新订阅并重新连接，再做同条件对照；不要同时调整 WARP、出口协议和客户端规则，以免无法判断原因

## 让节点改用 CDN {#cdn}

在用户中心「流量路由 → 协议」的 [AnyTLS 分页](https://oixcloud.com/user/anytls) 可以按节点选择「直连」或「CDN」，默认直连。官方客户端默认使用 Hollow，选择 CDN 的节点改走 AnyTLS；第三方客户端走 AnyTLS 直连，不受这里影响。仅支持此功能的官方客户端会读取这项设置，修改后同样要更新客户端订阅并建立新连接

只有 Edge 和 Home ISP 节点可以走 CDN，页面只列这些节点；未默认下发的 Home ISP 显示暂不支持流量路由。有外部中继的节点选了 CDN 也不走，页面会在该行提示

## 常见问题 {#troubleshooting}

| 现象 | 核对方式 |
| --- | --- |
| 已保存，但客户端没有使用 HTTP/3 | 先更新订阅并建立新连接；确认使用支持 HTTP/3 的 Hollow 连接、该节点没有选择 CDN，且智能回退没有选择普通连接 |
| 选择「仅 HTTP/3」后无法连接 | 检查当前网络的 UDP 连通性；改选「智能回退」或「关闭」，再更新订阅重试 |
| 某个独享 IP 没有变化 | 核对设置行和客户端实际使用的完整地址，每个地址分别保存 |
| 下载变慢却没有自动切换 | 回退只处理连接建立，不能按下载速度切换现有连接；改回「关闭」后更新订阅并重连对照 |
| 网站显示支持 HTTP/3，但无法判断节点是否生效 | 网站自身使用的 HTTP 版本与客户端到节点的传输是两段连接，不能相互证明 |

仍有问题时，通过 [服务单](/help/support) 提供客户端与版本、网络环境、节点名称或独享 IP、所选的选项、配置更新时间和具体报错；不要提供密码、Access Token 或完整订阅链接
