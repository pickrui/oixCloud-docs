# 中继与自建落地

先确定流量路径，再选择功能。网站的中继设置和客户端的代理链是不同入口

| 需求 | 使用方式 |
| --- | --- |
| 从一个站内节点进入，经一个或多个站内节点出站 | [内部中继](https://oixcloud.com/user/relay) |
| 通过站内入口转发到自己部署的落地服务器 | [外部中继](https://oixcloud.com/user/cusrelay) 的协议保持模式 |
| 转发至已有 SSH、远程桌面或游戏服务 | 外部中继的协议转换模式，按页面允许的端口设置 |
| 在本机组合已有代理节点 | [oixCloud 代理链](/oixcloud/policies) 或 [FlClash for oixCloud 代理链](/flclash/proxies) |

## 内部中继

内部中继把流量从一个站内节点转到其他站内节点再出站。页面上方的「中继路径」图展示你的配置，下方的「中继规则」列出路径中的每一段

### 添加多级路径

1. 打开[内部中继](https://oixcloud.com/user/relay)，点击「添加路径」
2. 按流量经过的顺序选择节点：第一个是入口节点，客户端连接它；最后一个是出口节点，流量从这里访问目标网站；中间可以插入中继节点，一条路径最多 17 个节点
3. 用每个节点右侧的按钮前移、后移或移除节点，「预览路径」会同步显示走向
4. 选择优先级后点击「保存路径」。如果改动会影响你从其他入口共用的路段，页面会列出受影响的入口和规则，确认后才保存

出口节点之后不需要再设置任何规则，也没有「不转发」之类的选项。只有出口节点上还有系统规则可能继续转发流量时，系统才会自动补上终点设置，它不会出现在规则列表中

### 添加单条规则

需要为同一个起源节点设置多个目标，或者只转发部分网站时，在「中继规则」中点击「添加单条规则」

1. 选择起源节点和优先级，再勾选一个或多个目标节点。已经存在的目标显示为「已添加」，不会重复添加
2. 同一优先级的多个目标组成负载均衡组；当前目标不可用时，自动改用同组其他可用目标或较低优先级的规则
3. 只转发部分访问时，在「仅转发指定域名/IP」中每行填写一条，例如 `example.com`、`+.example.com`、`1.1.1.1`、`example.com:443`；不要填写 `https://`、路径或查询参数，留空表示全部流量

规则列表中的「编辑路径」打开该规则所在的整条路径，「单条编辑」只修改这一段。编辑或删除某一段会影响所有经过它的路径

### 生效与状态

- 已生效：节点当前使用这条规则；备用：更高优先级的规则可用时暂不使用；不可用：起源或目标节点当前不可用；配置中：刚保存，等待状态更新
- 保存后更新订阅或托管配置，选中入口节点建立新连接，再检查实际出口
- 创建前查看起源和目标的 WARP 状态；启用 WARP 的节点不能作为普通中继使用

## 创建外部中继

1. 准备目标 IP 或域名、端口以及可管理的目标服务器。按页面说明填写 IPv4 解析信息
2. 选择「协议保持」或「协议转换」，再选择来源节点；不要把两种模式的部署命令互换
3. 协议保持模式按页面生成的命令部署落地服务，并确保目标监听端口与填写值一致；未指定时按个人端口规则处理
4. 协议转换模式连接已有服务，当前允许的目标端口为 `22`、`23`、`3306`、`3389` 或 `10000–65535`，以表单校验为准
5. 使用页面的目标检查，保存后更新客户端连接信息并验证实际业务

目标检查成功只说明该次检查可达，还需验证实际使用的 TCP / UDP 和应用协议。协议保持模式的接入信息包含账户连接凭据，应在自己的设备中保存

::: warning 切换功能前先记录配置
开启 WARP 会清理以该逻辑节点为来源或目标的内部中继，以及以它为来源的外部中继。关闭 WARP 不会自动重建这些设置
:::

## 排查顺序

- 保存被拒绝：检查权限、来源和目标冲突、WARP 状态及端口范围
- 提示与已有中继设置冲突：打开提示中的规则，用「单条编辑」调整或删除后，再保存路径
- 提示已为所有节点停用中继：在中继规则中删除起源节点为「所有节点」、目标为「停用中继」的那一条
- 提示与系统转发设置冲突：换用其他节点，或联系支持
- 目标不可达：确认监听地址、目标防火墙和服务状态，先直接验证目标服务
- 已保存但路径未变：更新订阅、重新连接，并确认连接的是入口节点
- 浏览器网站转发需求：外部中继不用于转发 Web 网站或网页管理面板，按服务使用规则选择其他合适方案
