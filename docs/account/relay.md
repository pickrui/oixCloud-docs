# 中继与自建落地

先确定流量路径，再选择功能。网站的中继设置和客户端的代理链是不同入口

| 需求 | 使用方式 |
| --- | --- |
| 从一个站内节点经另一个站内节点出站 | [内部中继](https://oixcloud.com/user/relay) |
| 通过站内入口转发到自己部署的落地服务器 | [外部中继](https://oixcloud.com/user/cusrelay) 的协议保持模式 |
| 转发至已有 SSH、远程桌面或游戏服务 | 外部中继的协议转换模式，按页面允许的端口设置 |
| 在本机组合已有代理节点 | [oixCloud 代理链](/oixcloud/policies) 或 [FlClash for oixCloud 代理链](/flclash/proxies) |

## 创建内部中继

1. 打开内部中继，添加规则，选择有权限的入口和目标节点
2. 如果只转发部分目标，填写页面支持的域名、IP 或端口条件；留空表示全部流量
3. 域名条件填写主机名，不要填写 `https://`、路径或查询参数；需要覆盖子域名时按界面的域名匹配说明设置
4. 保存后更新客户端配置，选中来源节点建立新连接，再检查实际出口

创建前查看来源和目标的 WARP 状态；启用 WARP 的节点不能直接按普通中继使用

## 创建外部中继

1. 准备目标 IP 或域名、端口以及可管理的目标服务器。按页面说明填写 IPv4 解析信息
2. 选择「协议保持」或「协议转换」，再选择来源节点；不要把两种模式的部署命令互换
3. 协议保持模式按页面生成的命令部署落地服务，并确保目标监听端口与填写值一致；未指定时按个人端口规则处理
4. 协议转换模式连接已有服务，当前允许的目标端口为 `22`、`23`、`3306`、`3389` 或 `10000–65535`，以表单校验为准
5. 使用页面的目标检查，保存后更新客户端连接信息并验证实际业务

目标检查成功只说明该次检查可达，还需验证实际使用的 TCP / UDP 和应用协议。协议保持模式的接入信息包含账户连接凭据，应在自己的设备中保存

::: warning 切换功能前先记录配置
开启 WARP 会清理以该逻辑节点为来源或目标的内部中继，以及以它为来源的外部中继。关闭 WARP 不会自动重建这些设置
:::

## 排查顺序

- 保存被拒绝：检查权限、来源和目标冲突、WARP 状态及端口范围
- 目标不可达：确认监听地址、目标防火墙和服务状态，先直接验证目标服务
- 已保存但路径未变：更新订阅、重新连接，并确认使用的是来源节点
- 浏览器网站转发需求：外部中继不用于转发 Web 网站或网页管理面板，按服务使用规则选择其他合适方案
