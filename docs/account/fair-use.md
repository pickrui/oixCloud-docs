# 公平使用

个人套餐供本人多设备使用，不能转借、合租、共享或转售；团队用途及人数以产品明确说明为准。账户的所有设备共同计入使用量，积分和限制也作用于账户，不按设备分别计算

公平使用积分衡量请求与节点资源的使用情况，与剩余流量、账户余额和权益额度分别计算。流量还有剩余，也可能因资源使用异常而受限

## 先查看临界值与积分 {#check}

1. 在 [套餐商店](https://oixcloud.com/user/shop) 查看当前所购套餐的「临界值」，下文记为 `K`
2. 在 [用户中心](https://oixcloud.com/user) 查看当前积分；初始值为 **50**，范围为 **0–50**
3. 打开 [账户信息](https://oixcloud.com/user/profile) 的「最近活动记录」，对照发生时间、活动请求及 Working nodes，点击节点数可查看该分钟上报的节点

`K` 是计算阈值的倍率，不是设备数、人数或直接允许的连接数。例如 `K = 2` 时，下表中的所有数量阈值乘以 2，积分加减值不翻倍。团队人数另看商品说明

按量付费套餐和临界值显示为 `∞` 的账户不参与下述分钟积分加减，但仍须遵守套餐条件与服务条款，也可能受到其他资源或账户限制

## 统计什么，怎样结算 {#calculation}

系统按账户汇总节点上报的分钟记录，通常每分钟处理一次，两项数据分别查表计分：

- **活动请求 `C`**：该分钟记录中的新增连接／请求计数之和，包括同一账户在不同设备、不同节点上的活动。它不是页面「长连接」列的当前连接数量，也不是浏览器标签页数或下载文件数
- **Working nodes `W`**：该分钟包含节点标识的上报记录条数，通常反映使用中的节点数量。同一节点若在该分钟上报多条记录会分别计入，不能简单按节点列表或去重后的节点名称数量代入

一个应用可能反复建立很多连接；自动测速、多节点并行使用、下载器及后台同步都可能增加上述数值。客户端本机的连接列表可用于定位来源，最终计分以平台收到的记录为准

每个参与结算的分钟记录按以下顺序计算：

```text
本次积分变化 = 活动请求积分变化 + Working nodes 积分变化
结算后积分 = min(50, max(0, 原积分 + 本次积分变化))
```

先合计两项，再把结果限制在 0–50；每项只取所在档位，不把前面所有档位的扣分累加。没有该账户的活动记录时，本次不加分也不扣分，因此完全断开并等待不保证自动涨分

上报、处理和页面刷新存在延迟，活动记录的查询时间范围也可能与某次结算不同。不要把墙上时钟经过一分钟理解为必定完成一次结算，也不要依赖断线、重连或切换设备来重置积分

## 活动请求积分表 {#requests}

所有时段均为**北京时间（UTC+8）**，与设备所在时区无关

- 常规时段：**00:00–02:00、08:00–24:00**
- 闲时时段：**02:00–08:00**，包含 02:00，不包含 08:00

| 每次积分变化 | 常规时段的活动请求 `C` | 闲时时段的活动请求 `C` |
| --- | --- | --- |
| +1 | `C < 100K` | `C < 300K` |
| −1 | `100K ≤ C < 150K` | `300K ≤ C < 450K` |
| −2 | `150K ≤ C < 200K` | `450K ≤ C < 600K` |
| −3 | `200K ≤ C < 300K` | `600K ≤ C < 900K` |
| −4 | `300K ≤ C < 1000K` | `900K ≤ C < 3000K` |
| −20 | `C ≥ 1000K` | `C ≥ 3000K` |

`100K` 表示 `100 × K`，其余同理。**恰好达到阈值就进入下一档**：例如常规时段 `K = 1、C = 100`，请求项为 −1，不是 +1

## Working nodes 积分表 {#nodes}

| 每次积分变化 | 常规时段的 Working nodes `W` | 闲时时段的 Working nodes `W` |
| --- | --- | --- |
| +1 | `W < 3K` | `W < 6K` |
| −1 | `3K ≤ W < 4K` | `6K ≤ W < 9K` |
| −2 | `4K ≤ W < 5K` | `9K ≤ W < 12K` |
| −5 | `W ≥ 5K` | `W ≥ 12K` |

闲时的节点阈值不能统一按常规阈值乘 3，应直接使用表中的 `6K、9K、12K`

## 计算示例 {#examples}

以下均假设 `K = 1`，数量为一个参与结算的分钟记录中的值：

| 场景 | 请求项 | 节点项 | 合计 |
| --- | --- | --- | --- |
| 常规时段，`C = 80、W = 2` | +1 | +1 | +2，最高到 50 |
| 常规时段，`C = 100、W = 2` | −1 | +1 | 0，积分不变 |
| 常规时段，`C = 150、W = 3` | −2 | −1 | −3 |
| 常规时段，`C = 310、W = 5` | −4 | −5 | −9，最低到 0 |
| 闲时时段，`C = 250、W = 5` | +1 | +1 | +2 |

例如原积分为 4，合计 −9 后变为 0，不会变成 −5；原积分为 49，合计 +2 后为 50

## 预警、限速与恢复 {#recovery}

| 条件 | 处理 |
| --- | --- |
| 从高于 20 分降至 1–20 分 | 触发积分预警；不会因为仍处于这个区间就每分钟重复通知 |
| 积分降至 0 | 对适用账户施加 **10 Mbps** 的公平使用限速；原本不限速或高于 10 Mbps 的才会被调低，已有更低限速不会被提高 |
| 积分恢复到高于 10，即至少 11 | 系统检查后解除本项 10 Mbps 限速，恢复所购套餐对应的速率设置；恰好 10 分仍不解除 |

两项均为 +1 时，每个有记录且已结算的分钟最多恢复 2 分。从 0 分恢复到超过 10 分，需要 **6 次这样的结算**，结果为 12 分；这不是保证 6 分钟恢复，也不要求等到满 50 分

减少造成异常的请求和多节点使用，保持正常轻量使用后观察积分。若仍有一项扣分，恢复可能更慢、积分不变或继续下降。积分预警与限速通知通过账户已配置的通知渠道发送，通知送达时间不等于限制生效时间

10 Mbps 是速率上限，理论换算约为 1.25 MB/s，实际速度还受线路、协议和其他限制影响。积分恢复只解除这一项限制；流量耗尽、套餐到期、余额不足或账户封禁不会因此自动解除

## 晚高峰与其他限制 {#other-limits}

晚高峰速率调整与上述积分是两项规则，也与凌晨的宽松计分时段不同。启用晚高峰调整的套餐在北京时间 **19:00–24:00** 适用以下计算：

- 套餐有速率上限时：套餐速率乘以配置的倍率，向下取整为整数 Mbps，最低为 1 Mbps；默认倍率为 0.5，实际是否启用、覆盖套餐和倍率以当前服务设置为准
- 套餐不限速时：晚高峰目标上限为 600 Mbps
- 计算出的晚高峰目标恰为 10 Mbps 时，使用 11 Mbps
- 已有更低速率限制时保留更低值；零点恢复本次被调低的速率，期间因套餐或其他原因发生的限速变化仍按其自身规则处理

晚高峰调整本身不扣积分。高速流量耗尽后的低速服务、按量余额要求及套餐有效期另见 [流量与计费](/account/traffic#limits)，「低速流量不限量」也不代表请求、节点、有效期和使用用途没有限制

## 违规与封禁 {#restrictions}

共享、合租或转售个人账户，未经允许的 P2P／BitTorrent、持续异常占用资源、扫描、攻击及其他违反服务条款的行为，可能导致限制服务、暂停或封禁账户。**积分正常或高于限速阈值不代表行为被允许，也不保证账户不会被封禁**

封禁与临时积分限速分别处理，不承诺自动解封。为防止规避，封禁的具体判定条件、检测方式和处置细节不公开；如对账户处理有疑问，请联系支持核查

## 出现限制时先做什么 {#help}

1. 保存限制提示、发生时间及所用节点，在用户中心核对积分、套餐有效期、流量和余额，先确定属于哪类限制
2. 在客户端查看活动来源，暂停大量并发下载、重复测速、异常重试或不必要的多节点任务
3. 检查是否把本机代理开放给他人，或泄露订阅、令牌；按 [账户安全](/account/security) 处理实际泄露的凭据
4. 观察后续已结算积分与账户状态；持续受限时按 [服务单说明](/help/support#restrictions) 提供核查信息

不要通过轮换账户、共享凭据或反复重置参数绕过限制。使用前阅读 [服务条款](https://oixcloud.com/tos) 和产品说明；多人使用应选择明确允许团队用途的方案
