# 账户与令牌安全

## 登录、退出与访问令牌

同账号的同类官方客户端会复用登录签发的令牌；客户端退出不会撤销服务器上的令牌。网页令牌页可以撤销令牌，所有使用该令牌的设备随后都需要重新登录；开启 iCloud 账户或 Apple TV 同步时，登录状态也可能随同步改变。手动创建的令牌按所选有效期到期，不要与登录签发的长期令牌混淆

## 首次登录定制客户端 {#first-client-login}

首次使用每种定制客户端时，可用邮箱和密码，或该客户端提供的「使用 Google 登录」，签发对应客户端的专属 Token。已有对应 Access Token 时，也可直接粘贴登录；填写 Token 本身，不是订阅网址

登录后，在 [Access Token 管理](https://oixcloud.com/user/token) 的「客户端登录签发」中找到对应客户端，之后可复制这条 Token 登录同类客户端。同账号同类客户端会复用令牌，不需要为每台设备重复创建

Google 入口目前适用于支持该功能的 oixCloud iPhone / iPad 版本和 FlClash for oixCloud。Apple TV 继续通过 [iPhone 同步账户](/oixcloud/apple-tv)；Helper、OpenClash、oixClash 按各自教程选择邮箱/密码或 Token，不假定都有 Google 按钮

## 使用 Google 登录客户端 {#google-client-login}

1. 在客户端登录页点击「使用 Google 登录」，在系统认证窗口或浏览器中继续
2. 选择与已有 oixCloud 账户邮箱一致的 Google 账户。此入口只登录已有账户，不会自动注册新账户
3. 完成验证后允许返回原客户端；若浏览器没有自动返回，点击完成页的「返回 App」
4. 等待账户信息和托管节点加载，再建立连接。超时或返回验证失败时，从客户端重新发起，不重复打开旧完成页

Google 登录需要客户端和网站同时支持。若当前版本没有入口，继续使用邮箱/密码或 Access Token；不要把 Google 密码填进 oixCloud 的密码框。需要账户密码时，可在 Gmail（包括垃圾邮件）查找初始密码邮件，或在 [网站登录页](https://oixcloud.com/auth/login) 用「忘记密码」重置

## 禁止客户端邮箱/密码登录 {#token-only}

1. 先确认需要的客户端已有可用 Token，或能够通过受支持的 Google 入口登录
2. 在 [Access Token 管理](https://oixcloud.com/user/token) 开启「禁止客户端使用邮箱/密码登录」，等待保存成功
3. 此后客户端和 API 的邮箱/密码登录被拒绝；现有 Token、网站登录和受支持的 Google 登录继续有效

旧页面可能把这个选项标为「仅允许 Access Token」，它实际限制的是邮箱/密码方式。如果某客户端没有 Google 入口且需要新签发 Token，可先在网站关闭此选项，用邮箱/密码登录后再开启

## 刷新客户端 Access Token {#refresh-client-token}

刷新会立即使旧 Token 失效，同账号同类客户端的所有共用设备都需要换用新 Token；客户端身份和绑定订阅保持不变

1. 打开 [Access Token 管理](https://oixcloud.com/user/token)，在「客户端登录签发」中找到目标客户端
2. 点击该记录的「重新生成」，确认影响范围后提交
3. 等待页面重新加载，复制新 Token，并更新所有使用这条 Token 的设备；通过 iPhone 同步到 Apple TV 的账户也需重新同步

禁止客户端邮箱/密码登录时仍可刷新，无需临时开放邮箱/密码登录。若请求失败或结果不明确，先重新加载令牌页确认当前 Token，再决定是否重试。手动创建的 Token 不提供此按钮，需要更换时请删除后重新创建

## 创建手工令牌 {#manual-token}

1. 在 [Access Token 管理](https://oixcloud.com/user/token) 点击「新增 Token」，选择有效期，填写便于识别的备注，并核对绑定的订阅
2. 确认创建后等待成功结果，页面重新加载时在「我创建的 Token」中查看新记录
3. 同一账户最多保留 10 条手工令牌，客户端登录签发的令牌单独显示，不占这份额度
4. 创建失败时先查看提示；结果不明确时刷新列表确认是否已创建，避免重复提交

手工令牌到期后不能继续认证，不会因使用而自动延期。不要把订阅网址填进 Token 登录框，也不要公开令牌截图

## Telegram 绑定与每日通知 {#notifications}

1. 打开 [账户设置 → 基础账户设置](https://oixcloud.com/user/edit#settings-basic)，在 Telegram 卡片确认绑定状态；未绑定时使用「前往绑定」并按机器人提示完成
2. 「已绑定账号」下显示「未设置 Telegram 用户名」仍代表已绑定，无需为了补用户名重复绑定
3. 在「每日通知订阅」分别设置邮件和 Telegram 开关，等待下方状态确认；未绑定 Telegram 时，该通知开关不可用
4. 保存失败或结果未确认时，先刷新页面核对实际状态再重试；正在保存时不要重复点击

每日通知开关只控制每日通知，不能据此判断安全、支付或服务状态提醒是否关闭。解绑前请确认不再需要该 Telegram 绑定

## 修改密码前确认影响 {#change-password}

修改密码会撤销当前账户的 Access Token、清除已有 Passkey，并删除旧主订阅地址。使用这些凭据的客户端需要重新登录或更新地址；原有 Passkey 不能继续用于网站登录，需要重新添加

1. 打开 [账户设置 → 修改密码](https://oixcloud.com/user/edit#settings-password)，填写当前密码、新密码及确认密码
2. 确认能更新其他设备的登录信息后提交，等待成功提示
3. 按提示重新登录网站，在令牌页重新获取所需客户端 Token，并更新使用旧主订阅地址的设备
4. 重新添加仍需使用的 Passkey；开启账户同步时，检查其他设备和 Apple TV 的登录结果

若禁止客户端邮箱/密码登录，重新获取令牌时按 [登录限制说明](#token-only) 处理。改密码不能替代逐项核对泄露内容，个人订阅地址等仍按下方对应表处理

## 添加和管理 Passkey {#passkey}

Passkey 用于网站登录，不是客户端 Access Token，也不是 TOTP 验证码

1. 打开 [账户设置 → Passkey 与两步验证](https://oixcloud.com/user/edit#settings-security)，选择「添加新 Passkey」
2. 输入当前账户密码；已启用 TOTP 时，再输入验证器当前生成的 6 位验证码，点击「继续」
3. 按浏览器提示使用面容、指纹或 PIN 等方式验证，等待网站提示成功，确认列表出现新记录
4. 可重命名记录，方便识别；删除前确认还有可用的登录方式，删除后该 Passkey 不能再登录此账户

取消或超时后，从「添加新 Passkey」重新开始。已提交使用的 TOTP 码不要重复使用，等待验证器生成新码；只完成系统验证窗口而没有网站保存成功提示，不能视为注册完成。浏览器提示不支持时，使用支持 Passkey 的浏览器并确认当前是 HTTPS 页面

## 启用 TOTP 两步验证 {#totp}

启用后，使用密码登录网站时还需输入六位动态验证码；页面明确要求二次验证的敏感操作也需按提示完成。Passkey 是独立的登录方式，不是一次性密码

1. 在同一账户设置页找到「TOTP」，用验证器扫描页面二维码，或手动录入显示的密钥
2. 输入验证器生成的 6 位验证码，提交激活，等待「TOTP 已成功启用」
3. 保留可恢复验证器的安全方式；二维码和密钥能生成验证码，不要放入截图、日志或服务单

关闭 TOTP 也需要有效验证码。验证失败时检查设备时间与所选账户，使用新生成的验证码再试；提示尝试过多时按页面要求等待。丢失验证器且无法完成验证时，通过 [服务单](/help/support) 说明情况，不要反复删除登录凭据

## 修改登录邮箱

1. 打开 [账户设置](https://oixcloud.com/user/edit#settings-email) 的「修改邮箱」，填写新邮箱并点「获取验证码」
2. 从新邮箱读取验证码，填写验证码和当前登录密码，再提交「修改邮箱」
3. 确认页面提示修改成功，核对账户中的邮箱；后续登录使用新邮箱

改邮箱的安全提醒使用变更前的联系方式，邮件提醒发往旧邮箱。如果收到的提醒不是本人操作，请立即联系支持。若提示密码错误次数过多，按页面提示等待后再试；功能被停用时无法从这里修改

## 哪些内容不能公开？

不要分享密码、Access Token、完整订阅地址、节点密码或证书私钥，截图和日志先隐藏这些内容。订阅泄露时在订阅页使用「重置」，然后更新所有设备的订阅与连接参数；该操作不会撤销 Access Token，令牌泄露需在令牌页单独刷新或删除

## 长期未登录的账户会被清理吗？

仅清理无有效套餐的账户：余额和佣金均不大于 0 时，连续 30 天未登录将自动删除；任一大于 0 时，期限为 90 天。登录网站或客户端，或保持登录后的有效访问，可重新计时

## 管理和撤销令牌

1. 打开访问令牌页，按备注与来源找到目标客户端或手工令牌
2. 更换一台设备时，先区分「仅退出这台设备」与「撤销服务器令牌」：官方客户端退出只清理本机登录状态
3. 确认泄露或不再使用时在网页删除目标令牌；同账号同款客户端可能共用它，删除会影响这些设备
4. 在仍需使用的客户端重新登录。若使用同步账户状态的设备，也检查同步后的登录结果

手工令牌有独立有效期，登录签发的令牌不会因为反复登录数量增多而自动回收。不要把所有设备共用一条客户端令牌理解为每台设备都能单独撤销

## 泄露后的对应处理

| 泄露内容 | 对应操作 |
| --- | --- |
| 某条个人订阅地址 | 在订阅管理删除或更换该地址，并更新使用它的客户端 |
| 主订阅地址或连接参数 | 使用页面的「重置连接参数 & 主订阅地址」，阅读影响说明后更新所有相关设备 |
| Access Token | 在令牌页刷新客户端签发的令牌，或删除对应令牌；重置订阅地址不能代替这一步 |
| 登录密码 | 按 [修改密码说明](#change-password) 更新令牌、主订阅与 Passkey；不要只换订阅 URL |

提交排查材料时保留错误和域名等必要信息，隐藏订阅路径中的密钥、登录 Token、节点密码、证书私钥及完整请求认证头
