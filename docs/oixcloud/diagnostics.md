# 请求记录与诊断

适用于 iPhone / iPad

1. 保持连接，只重现一次目标操作
2. 打开「活动」，切换到「请求」（网络图标），按域名搜索对应请求
3. 查看请求详情中的命中规则、来源、路由与出口
4. 对照当前模式、网络预设、规则优先级和所选策略组

看不到目标请求时，先检查流量是否进入客户端，是否被排除路由绕过，以及应用是否仍在复用旧连接

## 选择合适的诊断入口

| 现象 | 优先查看 |
| --- | --- |
| 域名无法解析或解析不符 | 「活动 → DNS」与 DNS 规则 |
| 网站走错节点 | 「活动 → 路由」与请求详情 |
| HTTPS 重写无效 | 「活动 → MITM」、证书与模块状态 |
| 切网后断开或反复重连 | 「活动 → 事件」 |
| 需要客服协助 | 「设置 → 诊断包」 |

## 导出诊断包

进入「设置 → 诊断包」，点击「导出诊断包」，等待系统分享窗口出现，保存文件后先检查内容，再通过服务单提供。若提示导出失败，保留错误并重试

应用生成的是匿名化诊断，设计上排除服务器地址、订阅 URL、凭据、证书及流量正文；手工附加的截图和日志仍需自行检查。诊断只说明导出时的状态，不等于已验证所有节点或应用

网络事件保留连接生命周期信息，有助于把发生时间与切网、断开、重连对应起来。反馈时附上时区与重现步骤

节点名称、域名、账户信息及其他个人数据应在公开分享前检查和隐藏。完整配置、Access Token 与证书私钥不要提交到公开仓库
