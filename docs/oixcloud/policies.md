# 策略组、自动选择与代理链

适用于 iPhone / iPad，配置可按同步范围发送到 Apple TV

在「代理 → 策略」中添加策略组，填写名称、选择类型并添加成员。保存后，还要在主页或对应分流规则中选择它，流量才会使用该组

| 类型 | 适合的需求 |
| --- | --- |
| 手动 | 由你选择当前成员 |
| 自动测速 | 依据配置的连接测试选择成员 |
| 故障转移 | 优先使用前面的成员，不可用时切换 |
| 负载均衡 | 将不同连接分配给可用成员 |
| 智能 | 根据实际连接表现学习路线，在建立连接失败时尝试其他成员 |

主页的「自动优选」是内置自动组；你创建的策略组会作为独立出口供选择。没有可用成员时，先检查成员来源、筛选条件与测试结果

自建组可同时选择独立节点、第三方订阅和托管订阅中的节点，操作见 [创建混合策略组](/oixcloud/proxies#mixed-group)。成员选择器按订阅显示时，「全部」只选中当前节点；来源后续新增的节点不会仅因此自动加入该组。内置「自动优选」的「包含所有代理」则是另一项设置，启用后应留意第三方节点也可能参与优选

## 调整测速与优先级

使用当前网络能访问的测试地址，先保留默认间隔。智能策略的优先级数值越小越优先，1.0 为中性；不要仅因为一次高延迟就把大量成员排除

自动切换通常影响新建连接，正在进行的下载或视频不应被当作切换验证依据。关闭目标应用的旧连接后再复测

### 自动优选的延迟为什么没有刷新 {#retesting}

当前维护版本的内置「自动优选」在后台进行定时检查时，如果上次检查后没有代理流量，会跳过本次重测。设置了间隔不等于空闲时仍不断测速；切网、连接失败或相关配置变化仍可触发检查。不能把此行为直接套用到所有自建策略组或其他客户端

需要立即比较节点时，在「代理 → 服务器」长按节点选择「测试延迟」；批量测试使用工具栏「全部测试」，文件夹也可从自身菜单测试成员。已有结果时，点击延迟数值可查看详情

确认测试完成后，再在主页核对自动优选当前选择，并新建一次目标请求检查出口。手动测得的低延迟不等于一定成为自动优选结果，也不证明目标服务可用；不要把未刷新的数字直接视为连接故障

以下按支持任意跳策略组的维护版本说明；旧版缺少选项时，先核对 [安装版本与下载入口](/oixcloud/connect)

1. 在「代理」切换到代理链区域，新建并命名，添加至少两个成员
2. 按入口到出口排列，每一跳都可选择节点，或符合条件的手动、URL Test、故障转移、负载均衡、智能策略组；同一节点或组不能重复出现
3. 保存后在主页或规则的目标中选中这条链
4. 对目标网站检查最终出口，再比较速度与稳定性

链越长不代表越快。任意一段不可用都会影响整条链；先分别验证每个节点，避免把链自身或相互依赖的策略组接回链中

### 入口组与后续跳组 {#group-hops}

入口组展开订阅、提供者与筛选后的有效成员须为独立节点，不能包含嵌套组、DIRECT／REJECT 或已带链路的成员，也不能再设置底层代理

**把策略组放在第一跳之后，会改变其他地方使用这个组时的路线**：
- 例如保存 `入口 A → 出口组` 后，即使规则直接指向「出口组」，组内具体节点也会先经过 A（不只在选中这条链时生效）
- 组内节点会派生为 `节点名 (via …)` 路线，并按经过前面各跳的结果分别测速；单独在其他地方选中原节点时，仍使用原路线

后续跳组中的嵌套组和 DIRECT／REJECT 保留自身行为，不继承前面的各跳；选中 DIRECT 会跳过前面的跳，REJECT 会拒绝连接。需要全部流量都经过入口时，应核对成员并移除这些例外。后续跳组至少需要一个可用的具体节点

每个新连接按组当前选择与健康状态确定路线，已有连接保留原路线。入口组测速只检查入口候选，不会逐一测试它们经过后续各跳的完整路线；测试整条链检查的是当时选中的完整路径

### 冲突与不可用 {#chain-troubleshooting}

同一个后续跳组只能使用一套前置路径，不能在另一条链中跟随不同的前置跳，也不能同时作为链入口、另设底层代理或充当其他组的底层代理。冲突会在所有相关链中报告，不能靠改选同一个组绕过

出现循环、成员无效或组内全部不可用时，先修正引用或恢复节点；这类错误会拒绝新连接，不会自动绕过该组直连。同步到 Apple TV 后，电视按自己的组选择和健康结果建立新连接，电视端不提供链编辑器

### 为策略组设置底层代理 {#underlying-proxy}

在策略组编辑页选择「底层代理」，可使用界面允许的节点、代理链或策略组。保存后，该组中的实际节点会通过 `节点名 (via 中继名)` 路线连接，并按完整路线分别测速；嵌套组与 DIRECT／REJECT 不继承这项设置

已有的 via 路线会被替换，不会继续叠加。带底层代理的组不能同时充当链入口、后续跳组或其他组的底层代理；出现循环或成员无效提示时先修正引用，不要依靠失败后直连
