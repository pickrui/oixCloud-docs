## 添加自有节点或订阅

### 添加单个第三方节点 {#single-node}

1. 打开「代理 → 服务器」，点工具栏的添加按钮，进入「添加代理」
2. 选择「链接」，粘贴一条完整的节点分享链接，例如 `ss://`、`vless://`、`trojan://`、`anytls://` 或 `hy2://`，再点「继续」；二维码则选择「二维码 → 继续」后扫描
3. 没有分享链接时，选择「手动 → 继续」，在编辑器选择协议，填写名称、地址、端口及该协议需要的密码、UUID、TLS、SNI 或传输参数，核对后「保存」
4. 回到「服务器」列表确认新节点；在主页打开节点选择器，选择它并连接，用 [请求详情](/oixcloud/diagnostics) 核对实际出口

使用便于区分的名称，参数应由节点提供方给出。支持哪些协议和选项，以当前版本的协议选择器和导入校验为准；同为 Clash／Surge 格式不代表其中每一种节点都能使用

HTTP／HTTPS 代理在「手动」中填写最清楚。「链接」入口只有在 HTTP(S) 地址同时包含用户名、密码、显式端口且没有业务路径时，才将其识别为单节点；其他 HTTP(S) 地址会按订阅下载。不要把代理服务地址当作订阅地址反复导入

### 添加第三方订阅 {#third-party-subscription}

1. 从提供方取得完整的 Clash／Surge 兼容订阅 URL，确认它返回节点内容，而非账户登录页或购买页
2. 打开「代理 → 服务器 → 添加 → 链接」，粘贴 URL，点「继续」；订阅二维码也可从「二维码」入口读取
3. 若提供方要求 `Remnawave HWID`，先了解开启后会经 HTTPS 向该订阅发送本机设备标识，再按需开启；普通导入无此要求时保持关闭
4. 等待下载和解析完成，在「服务器」中展开新增订阅，核对名称与节点数量，再在主页选择其中的节点并验证连接

这个入口保存订阅来源，供后续更新；从 Clash／Surge 内容中提取受支持的节点，**不会同时安装那份配置的全部策略组和分流规则**。部分条目不支持时，可能只导入其余可用节点；在「活动 → 事件」查看跳过条目及原因，不能把“添加成功”理解为完整兼容

### 从配置文件导入 {#profile-file}

保持「规则」模式，再打开「代理 → 策略 → 路由规则 → 更多 → 导入规则集」；文件导入不在「添加代理」的方法列表中。此入口可识别受支持的 Clash YAML（`.yaml`／`.yml`）和 Surge 配置（如 `.conf`）中的节点、策略组与规则

**完整配置可能增加影响现有流量的规则、策略组和相关资源**。仅想增加节点时，优先使用上面的节点订阅入口；需要导入完整配置时，先保留当前来源或可恢复副本，再选择文件，查看导入摘要和不支持项后确认。导入后分别在「服务器」「策略」和「路由规则」中核对结果，用新请求检查匹配顺序与出口

本地文件是导入时的内容副本，没有整份文件的远程更新地址；文件内单独引用的远程代理集或规则集仍按各自来源管理。导入成功不等于 DNS、模块或原客户端全部功能都已迁移

### 一键导入链接 {#add-proxy-link}

支持此功能的版本可打开 `oixcloud://add-proxy?link=…` 或 `anywhere://add-proxy?link=…` 链接；2.1.6（520）起也可在添加代理页粘贴、扫描或输入完整的一键导入链接。这里的省略号仅示意格式，不可直接用于导入

按导入页核对其中携带的是单节点还是订阅，再确认保存，回到列表检查新增条目。链接可能包含节点凭据或订阅密钥，不要交给公开转换网站。没有对应入口或无法识别时，确认安装版本，或使用提供方给出的原始节点／订阅链接

## 与 oixCloud 托管节点一起使用 {#managed-mix}

独立节点、第三方订阅与 oixCloud 托管订阅可以同时保存在代理列表中，不需要把另一家的节点写进托管订阅。按前面的步骤添加第三方来源后，保留已有托管订阅，在主页节点选择器中按订阅名称找到并选择需要的出口

规则模式下，主页的选择用于路由目标为「代理」的流量；明确指定节点、策略组、直连或拒绝的规则仍按各自目标处理。只把第三方节点加入列表，不会自动把所有网站都改走该节点

若使用内置「自动优选」，先检查「代理 → 策略 → 自动优选」中的「包含所有代理」和成员选择。开启包含所有时，第三方节点也可能成为候选；只希望托管节点承担日常流量时，关闭包含所有并只勾选所需托管成员，再安排下面的网站例外

### 只让指定网站走第三方出口 {#route-third-party}

1. 在主页选择日常使用的托管节点或仅含托管成员的策略组，保持「规则」模式
2. 打开「代理 → 策略 → 路由规则 → 更多 → 添加规则」，选择「域名尾缀」，填写实际目标域名，例如 `example.com`
3. 将路由目标直接设为已添加的第三方节点，或设为包含第三方节点的策略组，保存规则
4. 新建目标请求，在「活动 → 请求」的详情中确认命中该规则、出口为第三方节点；再检查一个未设例外的目标仍按原有分流处理

不要把完整网页 URL 填入域名字段，也不必为简单的网站例外创建代理链。未命中例外的流量继续按其他规则和兜底路由处理；规则优先级和 [网络预设](/oixcloud/networks) 也可能影响实际结果，排查见 [分流规则](/oixcloud/routing)

### 把两种来源加入同一策略组 {#mixed-group}

希望在托管与第三方节点之间自动选择时，可创建自己的自动测速组：

1. 打开「代理 → 策略 → 添加策略组」，填写独立名称，例如「混合出口」，类型选择 `URL Test`（自动测速）
2. 点「添加成员」，按「订阅」分组展开 oixCloud 与第三方订阅，分别勾选需要的节点；独立节点可在对应列表或文件夹中选择
3. 点「完成」返回编辑页，核对成员和可访问的健康检查地址后「保存」
4. 在主页选择「混合出口」，或把指定网站的规则目标设为该组，用新请求确认实际选中的成员。需要固定使用某个出口时，也可直接在主页或规则中选具体节点

成员选择器的「全部」只勾选当前已有的节点，**不表示这份订阅今后新增的节点都会自动加入自建组**。订阅更新后应检查新增、移除或不可用成员；已有导入组若带动态代理集来源，则按其来源设置更新，不能据此推断手动勾选的组也有相同行为

把节点放在同一组供选择，不会让流量逐个经过它们。只有确实需要多跳转发时才配置 [代理链或底层代理](/oixcloud/policies#underlying-proxy)

## 用文件夹整理独立节点 {#folders}

以下文件夹操作适用于 iPhone / iPad 的 2.1.6（520）及后续支持版本；是否可下载以所用发布渠道为准。本页节点选择示意图不展示文件夹编辑，Apple TV 不据此视为具有相同管理界面

1. 在「代理」选择「服务器」区域，从工具栏的更多操作中点「新建文件夹」
2. 填写名称，点「添加代理」选择未归入其他文件夹的独立节点，完成选择后保存
3. 长按节点，在操作菜单选「移到文件夹」；已归类节点可「移出文件夹」，也可移到其他文件夹
4. 长按文件夹选「编辑」，可修改名称、添加成员及拖动成员排序；文件夹之间的顺序通过「重新排序代理」调整
5. 展开文件夹确认节点和顺序，再回主页检查当前出口；整理文件夹本身不会切换连接

文件夹只整理独立节点，不收纳订阅中的节点，也不是策略组或代理链。同一个节点只在一个文件夹中显示

::: info 删除文件夹与删除节点不同
**删除文件夹不会删除其中节点**，节点会回到未归类列表；编辑时移除成员也只是移出文件夹。直接删除节点是另一项操作，应先检查规则引用。文件夹随「代理」类别进行 iCloud 同步，兼容条件见 [同步与版本](/oixcloud/sync#folder-sync)
:::

在订阅的操作菜单中使用「更新」。托管 oixCloud 节点使用账户页的「刷新节点」，账户信息下拉刷新并不等于重新获取节点

### 更新第三方节点与订阅 {#update-third-party}

| 来源 | 更新方法 |
| --- | --- |
| 手动或分享链接添加的独立节点 | 长按节点选「编辑」，修改提供方变更的参数并保存；它没有订阅地址可刷新 |
| 第三方 URL 订阅 | 在「服务器」长按订阅标题选「更新」，或使用该订阅行的更新按钮；等待成功标记，出现警告时点开原因 |
| 本地配置文件 | 保留新文件并重新导入、核对结果；原文件改变不会自动更新已导入内容 |

自动更新在该订阅的「编辑」中开启，填写「自动更新间隔（分钟）」并保存。应用可运行时会检查到期订阅，重新打开应用也会检查；不要将此设置理解为 iOS 关闭或挂起应用后仍保证定时下载

更新可能新增、替换或移除订阅内节点，应复查主页选择、策略组成员及规则引用。直接修改订阅节点的连接参数可能被下次更新覆盖；需要长期独立维护时，使用独立节点。若订阅地址被提供方更换，按新 URL 添加并验证，再处理旧订阅和它的引用

提供「预览配置更新」的订阅属于完整配置来源，更新可能涉及策略组和规则；先预览差异，再决定应用，并核对本地修改保留情况。普通节点订阅没有相同的整份配置更新流程

第三方订阅菜单中的「恢复上次更新前版本」会用本机保留的上一版本回退该订阅，影响当前节点与引用，操作前先确认要保留哪一版；它不是重新下载最新内容，也不保证总有可用历史版本

### 刷新托管节点与筛选 {#update-managed}

在「oixCloud → 节点筛选」按线路、地区和名称设置条件，查看预览后保存，客户端会重新获取托管节点。恢复默认会回到智能优选；筛选不会增加套餐权限，同一账户的同款客户端会共享设置，详见 [订阅与筛选](/account/subscriptions)

账户页「刷新节点」和托管筛选只管理托管来源，不会替第三方订阅更新。更新第三方节点时也不需要删除托管订阅或退出账户

## 添加、更新或混用失败时 {#import-troubleshooting}

| 现象 | 检查方法 |
| --- | --- |
| 链接无法识别 | 检查是否完整、是否有多余空格及协议是否受支持；手动填写时核对端口、认证、TLS、SNI 和传输参数 |
| 订阅下载失败或没有节点 | 检查 URL、有效期、提供方权限、网络和格式；在「活动 → 事件」确认是否全部节点都被跳过，不要使用账户网页代替订阅 |
| 节点已添加，网站仍走托管出口 | 检查主页选择、规则模式和明确指定的规则目标；用新请求查看命中结果，旧连接可能仍保留原出口 |
| 更新成功后某组缺少新节点 | 检查自建组的显式成员；成员页「全部」不是持续跟随整份订阅的开关 |
| 更新失败或提示已保存但未应用 | 点开订阅行的错误原因，处理后重试；保留原来源和现有内容，再核对请求出口，不要仅看更新时间 |

完整订阅链接、节点凭据和诊断包不要提交到公开 Issue 或不可信转换网站。删除第三方来源前，先检查并调整主页选择、个人规则、策略组和代理链对它的引用

## 测试延迟

可测试单个节点或批量测试，再查看延迟详情。一次连接测试不能代表持续带宽，也不能证明指定流媒体可用；只比较同一网络、相近时间下的结果

## 删除与恢复

删除节点或订阅前确认是否被策略组、代理链或规则引用。「最近删除」可恢复本机三天内删除的节点与订阅，不是跨设备回收站；超过期限不能从这里恢复

恢复后核对当前选择和关联规则，再实际连接验证
