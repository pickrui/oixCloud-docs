# 节点、策略组与分流

先分清三个问题：流量有没有进入客户端、应该走哪条路线、路线最终使用哪个节点

| 名称 | 作用 | 举例 |
| --- | --- | --- |
| 系统代理 / VPN / TUN | 让应用流量进入客户端 | FlClash for oixCloud 开启系统代理或虚拟网卡 |
| 分流规则 | 按域名、IP 等条件决定去向 | 公司域名直连，其他请求走代理 |
| 策略组 | 从一组节点中选择出口 | 手选、自动测速、故障转移 |
| 节点 | 实际建立代理连接的服务器 | 选择你有权限使用的节点 |
| 订阅 | 更新节点与部分配置的来源 | 服务商提供的托管配置 |

## 三种模式

- **规则**：按规则决定代理、直连或拒绝，适合日常使用
- **全局**：主要流量使用所选出口，适合短暂对照排查；客户端对本地网络的处理仍受其设置影响
- **直连**：不通过代理出口访问，不用于检验远程节点是否正常

在 oixCloud 中，规则的「代理」目标按当前代理选择继续路由；指定节点或策略组则使用指定出口。FlClash for oixCloud 的规则目标必须对应当前配置中存在的节点或组，`PROXY` 可能只是某个配置里的组名，不是通用的“当前代理”关键字，不能直接跨客户端照抄

## 三种凭据不要混用

Access Token 用于客户端账户登录，订阅地址用于获取配置，节点密码用于连接服务器。退出客户端、撤销令牌与重置订阅也不是同一个操作，详见 [账户与令牌安全](/account/security)
